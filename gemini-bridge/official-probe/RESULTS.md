- [FAQ](https://antigravity.google/docs/faq): использование входа Antigravity сторонними агентами нарушает условия; обёртки `agy` внутри сторонних агентов/приложений не поддерживаются на потребительских тарифах. - [Headless](https://antigravity.google/docs/cli/headless): JSON/NDJSON — события готового агента, не публичный интерфейс сырого function calling внешнего клиента.

- [MCP](https://antigravity.google/docs/mcp?tab=cli): поддержанный путь расширения инструментов внутри Antigravity. Его работа этим этапом не проверена.

## Продолжение после пользовательских скриншотов

Пользователь показал веб-интерфейс: у выбранного аккаунта значок Pro, Hydrogen выбран, Argon виден без замка, Carbon под замком. Адрес аккаунта здесь не сохраняется. Это подтверждает состояние меню на снимке, не успешную генерацию и не совпадение с аккаунтом CLI. Каталог веб Gemini не равнозначен каталогу Antigravity.

Повторный `agy models` 14 ноября дал тот же список из шести идентификаторов; версия CLI — 1.5.9. `download_cli.py` повторно сверил локальный бинарник с текущим официальным манифестом: `Existing CLI matches release`. Новая копия не скачивалась. Запрос манифеста через внешний инструмент чтения страниц сначала истёк по времени; сверка затем выполнена локально штатным загрузчиком с проверкой SHA512.

Попытка применить `--settings` к подкоманде `models` отклонена парсером: `flags provided but not defined: -settings`. Изменение отменено. Поэтому временные настройки генерации не считаются подтверждением режима авторизации команды каталога; аккаунт CLI по-прежнему не установлен. Генерация не повторялась: причина прежнего регионального отказа не устранена.

Добавлен `availability.py`: отдельные статусы для веб-наблюдений, каталога CLI и генерации. Отсутствие модели не приравнивается к окончательному запрету по подписке. Неуспешное обновление каталога не подменяется старым успешным результатом. В `probe.py` запрос блокируется, если модель не перечислена в последнем каталоге, защитные настройки изменены или сохранён региональный отказ. `--recheck` снимает только последний предохранитель после восстановления официального доступа; прокси, тариф и аккаунты не переключает.

Самостоятельная проверка аккаунта без извлечения секретов: в уже открытом Antigravity CLI посмотреть адрес в заголовке и сопоставить с аккаунтом Pro на снимке. Не использовать `/logout`: он удаляет сохранённую авторизацию. Документированная команда безопасного `whoami` без возможного запуска браузерного входа не найдена. При необходимости пользователь может передать снимок заголовка с замазанной частью адреса и меню `/model`; вход заново и публикация cookies не нужны. До этого тождество аккаунтов не доказано.

Carbon остаётся необязательной целью: по текущей таблице Antigravity он требует Ultra; на снимке заблокирован. Подписка, оплата и регион не менялись. Для официального Argon/Orchestrator на Jio нужны права именно Antigravity, а не только доступ в веб Gemini. Продолжение до нативных инструментов и субагентов блокирует неподтверждённый официальный доступ; готовый мост не заявляется.

Локальные тесты после новых изменений: `Ran 10 tests ... OK`. Проверяют предохранители и разделение доказательств, а не успешную генерацию. Исследователь сверил публичные документы авторизации, моделей и FAQ; файлов не менял. Исполнитель `checker` снова недоступен, проверки выполнены Kin.

## Решение

Официальный мост-провайдер для OpenCode поверх потребительского входа не реализуется как «поддерживаемый официальный путь». Допустимое направление — самостоятельный официальный Antigravity со своими инструментами/MCP. До восстановления поддерживаемого доступа к сервису нельзя принимать прототип как работающий транспорт.

Нужно проверить в самом Antigravity: выбранный аккаунт, соответствие страны условиям доступности и права Jio у поддержки Google/Jio, не отменяя пробный период и не меняя подписку. При неподдерживаемой стране использовать сервис нельзя до появления официальной доступности. Автосмена IP не является исправлением прав доступа.

Для официального CLI по-прежнему не проверены: успешная генерация, нативные инструменты, рассуждения, внешние MCP-инструменты, сохранение многоходового контекста, отмена, субагенты и длительная нагрузка. Успех короткого веб-цикла выше к CLI не относится. Ошибки Code Assist из старого README не переносились на новый CLI как доказательство.

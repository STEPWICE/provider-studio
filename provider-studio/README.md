# Provider Studio

Красивый минималистичный GUI для добавления кастомных AI-провайдеров и моделей
в **opencode**, а также для **Kilo Code**, **Cline**, **Roo Code**, **ZCode**,
**DeepSeek Harness** и любых других harness-ов с поддержкой кастомных эндпоинтов.

Рантайм без зависимостей — чистый Node.js. `esbuild` и `postject` нужны только
для сборки `.exe` и стоят в `devDependencies`.

## Запуск

```powershell
cd provider-studio
npm start
```

Откроется браузер на `http://localhost:5173`. Двойным кликом — `start-provider-studio.cmd`.

> Если порт занят, сервер сам возьмёт следующий свободный (5174, 5175…).

## Сборка в один .exe

```powershell
npm install   # один раз — esbuild + postject
npm run build
```

Результат: `dist/provider-studio.exe` (~88 МБ — внутри целый Node-рантайм).
Файл самодостаточен: ни Node, ни папка `public/` рядом не нужны — GUI зашит
в бинарник как SEA-ассеты.

Как это работает и почему именно так:

- Формат single-executable принимает **только CommonJS**, а проект целиком на ESM,
  поэтому `server.mjs` сначала собирается в CJS через `esbuild`.
- Бандлер превращает `import.meta.url` в `{}`, так что `fileURLToPath(import.meta.url)`
  молча стал бы падать. Поэтому корень статики ищется через `argv[1]`/`execPath`
  (`src/assets.mjs`), а сборка **проверяет**, что в бандле не осталось `import.meta`.
- `postject` не читает пути с не-ASCII символами (а репозиторий вполне может лежать
  в папке с кириллицей), поэтому инъекция всегда делается в ASCII-каталоге в `%TEMP%`,
  а готовый файл копируется обратно.
- Последний шаг билда — запуск самого `.exe` с самопроверкой: он отдаёт `/`, `/app.js`,
  `/style.css`, `/api/state` и проверяет, что обход каталога по-прежнему блокируется.
  Сборка падает, если UI недостижим, — «собралось» значит «работает».

## С чего начать (если делаешь это впервые)

Нажми **«Мастер настройки»** в левом нижнем углу — 4 шага:

1. **Провайдер.** Выбираешь сервис из списка (OpenRouter, DeepSeek, Anthropic,
   OpenAI, Groq, Together, Mistral, Z.ai, Ollama, LM Studio) — Base URL, формат
   API и имя переменной окружения подставляются сами. Base URL — единственное
   поле, которое невозможно угадать, а ошибка в нём проявляется только позже,
   уже внутри opencode, как 404 на каждом запросе. Есть вариант «Другой
   (вручную)» для любого совместимого эндпоинта.
2. **Ключ.** Вставляешь API-ключ; для локальных (Ollama, LM Studio) он не нужен.
   Рядом сразу видно, задана ли нужная переменная окружения, и готовую команду
   `setx`, если нет.
3. **Модели.** Список подтягивается с сервера; отмечаешь нужные. Если сервер не
   отдаёт `/models`, показывается встроенный список пресета.
4. **Запись.** Итоговая сводка, затем обычный diff — на диск ничего не идёт,
   пока не подтвердишь.

Мастер не пишет в файл напрямую: он заполняет основную форму и уходит в тот же
путь «diff → подтверждение → запись», что и ручной режим.

## Что делает

- Заполняешь **Название / Base URL / API-ключ / Формат API** — как в UI Kilo Code.
  Формат API определяется по Base URL автоматически, пока не выберешь вручную.
- Добавляешь модели: **Model ID, контекст, макс. выход, типы входа/выхода, reasoning, tools**.
- Выбираешь куда добавить:
  - **opencode** — пишет напрямую в `~/.config/opencode/opencode.jsonc`: блок провайдера
    с `npm` (пакет AI SDK), `name` (отображаемое имя), `options.baseURL`, `options.apiKey`
    и модели с `modalities` / `limit` / `attachment` / `reasoning` / `tool_call`.
    Модель по умолчанию выбирается в выпадающем списке рядом с «Применить».
  - **Kilo / Cline / Roo / ZCode / DeepSeek Harness / Generic** — генерирует конфиг
    на копирование + пошаговую инструкцию (поля совпадают с их UI).
- «Скопировать JSON» — кладёт манифест в буфер, ключ заменяется на placeholder.

## Защита от ошибок (то, что избавит от проблем)

| Возможность | Как включить | Что делает |
|-------------|--------------|-----------|
| **Комментарии и форматирование сохраняются** | всегда | Конфиг правится текстовым патчем по месту, а не перезаписывается как JSON: комментарии, отступы и однострочные `{ … }` остаются как были |
| **Показ diff до записи** | кнопка «Показать diff» | Показывает построчно, что именно изменится в файле. Пока не нажмёшь «Записать в файл», на диск ничего не идёт |
| **Защита от конкурентной правки** | всегда | Запись отправляется вместе с хешем прочитанного файла. Если файл успел измениться (руками или другим инструментом), запись отклоняется с 409, а не затирает чужие изменения |
| **Удаление провайдера** | кнопка `×` в списке | Удаляет по-настоящему: сначала показывает diff, потом убирает блок из `opencode.jsonc` (с бэкапом и откатом) и из списка Studio. Переназначает `model`/`small_model`, если они ссылались на удаляемый |
| **Переименование ключа** | кнопка `✎` в списке | Переименовывает ключ провайдера, сохраняя сам блок и его комментарии |
| **Выбор файла конфига** | список в шапке | Если конфигов несколько (глобальный/проектный), выбираешь, в какой писать |
| **Авто-бэкап перед изменением** | всегда | Перед любым изменением `opencode.jsonc` снимается снапшот в `data/backups/` |
| **Ручной бэкап** | кнопка «Бэкап» | Создать снапшот прямо сейчас |
| **Восстановление** | «Восстановить» у любого бэкапа | Возвращает файл байт-в-байт, вместе с комментариями (перед этим текущий тоже бэкапится) |
| **Валидация** | кнопка «Проверить конфиг» | Ищет неизвестные поля провайдера/модели, `apiKey`/`baseURL` не на своём уровне, пакет в поле `name` вместо `npm`, ключи вида `$VAR`, незаданные переменные окружения, неполный `limit`/`cost`, `output` больше `context`, отсутствие `attachment` у вижн-моделей, битую модель по умолчанию, некорректный `options.timeout`, мусор в массиве `env`, два провайдера на один Base URL, отсутствие ключа и env у публичного провайдера |
| **Халява** | кнопка «Халява» | Ежедневный дайджест с публичного борда Ailyre: какие провайдеры прямо сейчас раздают (промо, триалы, студенческие тарифы) и какие новости влияют на доступ. Кэш на 6 часов, при недоступности сети — вчерашний кэш с пометкой, а не ошибка. Только чтение: кнопок «забрать» нет, у каждой записи ссылка на источник |
| **Только бесплатные** | «Диагностика» → «Обновить модели» | В плане обновления у новых моделей видна метка `free` (по заявленной провайдером нулевой цене, а не по названию), галочка оставляет к записи только бесплатные. Неизвестная цена бесплатной не считается |
| **Проверка соединения** | кнопка «Проверить» | Пробует достучаться до Base URL и подсказывает, если ключ/URL кривой. Ссылка `{env:VAR}` разворачивается так же, как это сделает opencode, а формат API определяет заголовок (`Authorization` или `x-api-key`) |
| **Редактирование существующих** | клик по провайдеру в списке | Загружает провайдера/модели в форму, меняешь и жмёшь «Применить» |
| **Импорт из opencode** | «Импортировать из opencode» | Подтягивает провайдеров из конфига, чтобы их можно было править |
| **Обнаружение моделей** | «🔍 Обнаружить модели» | Автоматически подтягивает список моделей с сервера (`/models`) по Base URL + ключу |
| **Фильтры моделей** | в окне обнаружения и в мастере | Поиск + фильтры «Бесплатные», «С вижном», «С reasoning» |
| **Цена и признак «бесплатно»** | в списках моделей | У каждой модели видно `$вход / $выход` за 1M токенов либо метка `free`. Берётся из ответа провайдера (`access_tier`, `pricing`), а не угадывается по названию; единицы нормализуются (per-token у OpenRouter и per-1M у других приводятся к одному виду). Найденные цены попадают в конфиг как `cost` — одинаково и через «Обнаружить модели», и через мастер |
| **Диагностика** | «Диагностика» | Проверяет всё сразу: конфиг + доступность каждого провайдера + модель по умолчанию. Различает «сервер лёг», «ключ не принят» и «ключ не отправлен» |
| **Автоисправление** | «Диагностика» → «Исправить автоматически» | Чинит всё однозначное: мусорные поля, ключ/адрес не на своём уровне, `$VAR` → `{env:VAR}`, открытый ключ → ссылка на переменную, неполные `limit`/`cost`, левые `modalities`/`status`, висячую модель по умолчанию. Сначала показывает обычный diff, пишет только после подтверждения, перед записью — бэкап. Что требует человека (незаданная переменная, пустой список моделей) — перечисляет отдельно |
| **Обновление моделей** | «Диагностика» → «Обновить модели» | Сверяет конфиг с живым `/models` каждого провайдера: показывает, что добавилось, а с галочкой — и что пропало с сервера. Существующие записи не перезаписываются, ручные правки сохраняются. Запись — после подтверждения, с бэкапом |
| **Самопроверка** | «Диагностика» → «Самопроверка» | Проверяет сам инструмент: версия Node, запись в каталоги данных и бэкапов, чтение и разбор конфига, прокси, доступность справочника models.dev. Недоступный каталог — предупреждение, а не приговор: без него инструмент работает |
| **Откат последней правки** | кнопка «Отменить» | Возвращает конфиг к состоянию до последней записи (применение, автофикс, обновление моделей, смена default, переименование, удаление, восстановление). Перед откатом текущий файл тоже бэкапится, так что ошибочный откат сам откатываем из списка бэкапов. Одноуровневый по design: после отката откатывать уже нечего |
| **Наблюдение за файлом** | автоматически | Раз в 5 секунд сверяет хеш конфига на диске. Если форма пустая — молча подхватывает новый хеш, если есть несохранённые правки — показывает жёлтый баннер с кнопкой «Обновить», чтобы следующая запись не умерла с 409 |
| **Проверка одной модели** | «⚡» в строке модели | Отправляет один пробный запрос (~16 токенов) к конкретной модели без пакетной очереди. Результат — та же метка `✓`/`₽`/`↻`/`✕`, что и у «Проверить все» |
| **Отчёт для issue** | «Диагностика» → «Скопировать отчёт» | Копирует сводку последнего прогона диагностики в markdown: провайдеры, конфиг-проблемы, путь, default-модель. Ключи вида `sk-…`, Bearer и значения `apiKey` затираются, ссылки `{env:…}` сохраняются — без них отчёт не объяснит проблему с переменной |
| **Проверка боем** | шаг 4 мастера | Отправляет один реальный запрос выбранной модели (16 токенов — дешевле шлюзы отвергают). «✓ Применено» означает лишь «файл записан» — а это проверяет, что связка действительно работает. Формат `openai-responses` пробуется через `/responses` со своим телом, а не через `/chat/completions` |
| **Проверка всех моделей сразу** | «⚡ Проверить все» | Прогоняет по одному настоящему запросу к каждой модели, по 3 параллельно с паузой между ними. При серии 429 пауза удваивается, а потом проверка останавливается, чтобы не выжечь лимит. Результат помечается прямо у модели: `✓` работает, `₽` не входит в тариф, `↻` шлюз отклонил временно, `✕` не отвечает. Модели, до которых не дошли, честно перечисляются как непроверенные, а не выдаются за сломанные |
| **Характеристики из models.dev** | автоматически при обнаружении | Пробелы в контексте, лимите выхода, вижне и reasoning заполняются из открытого каталога models.dev (7435 моделей). Заполняется только то, чего провайдер не сообщил сам, и только когда источники согласны между собой — иначе стоит пометка «спорно». **Цены оттуда не берутся никогда**: одна и та же модель у одного провайдера бесплатна, у другого платная |
| **Смена модели по умолчанию** | «Диагностика» → «Сделать основной» | Если `model` указывает на недоступного провайдера, а рабочий уже настроен — переключает одной кнопкой, меняя ровно одну строку конфига. Сначала предлагаются провайдеры без проблем; те, у кого не принят или не задан ключ, идут ниже и с пометкой, а если здоровых нет вовсе — об этом говорится прямо, а не молча предлагается сломанный |
| **Установка переменной окружения** | «Задать сейчас» у имени переменной | Выполняет `setx` за тебя, ключом из формы. Раньше здесь была команда, которую надо было скопировать вручную — именно на этом шаге настройка обычно и застревала |
| **Индикатор доступности** | точка в списке слева | Зелёная — отвечает, жёлтая — сервер жив, но ключ не принят или не отправлен, красная — недоступен, серая — ещё не проверялся |
| **Раскладка в две колонки** | всегда | Слева редактор, справа — диагностика, проверка конфига и бэкапы. Кнопки этих панелей стоят над ними, а не под редактором ниже сгиба. У правой колонки есть минимум (300px) и максимум (520px): уже — текст превращался в вертикальную «лапшу», шире — панель начинала перевешивать саму форму. Ниже 1124px окна колонки схлопываются в одну |
| **Работа через прокси** | автоматически | Пробы уважают `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY` и системный прокси Windows. Локальные провайдеры (`127.0.0.1`, RFC1918) через прокси не гоняются |
| **Мастер настройки** | «Мастер настройки» | 4 шага для новичка: пресет провайдера → ключ → модели → diff. Base URL и формат API подставляются из пресета |
| **Проверка переменной окружения** | автоматически | Рядом с именем переменной видно, задана ли она и в какой области. `{env:FOO}` при незаданной `FOO` авторизуется пустой строкой — это заметно только по 401, поэтому запись с незаданной переменной требует подтверждения |
| **Поиск по провайдерам** | появляется от 6 провайдеров | Фильтр списка в сайдбаре, `/` ставит курсор в поиск |
| **Горячие клавиши** | всегда | `Ctrl+S` — применить, `Ctrl+D` — показать diff, `/` — поиск, `Esc` — закрыть окно |
| **Запоминание выбранного конфига** | всегда | Выбранный в шапке файл восстанавливается при следующем запуске — но только если он всё ещё есть в списке |

Хранилище: `data/backups/` хранит до 30 последних бэкапов, старые удаляются автоматически.

### Обнаружение моделей

Кнопка «Обнаружить модели» запрашивает `/models` у указанного Base URL и строит список моделей.
Способности (vision / reasoning / free) подбираются автоматически по имени модели и метаданным
(где провайдер их отдаёт). В окне можно отфильтровать по типу и отметить галочками нужные —
они попадут в список моделей провайдера.

Чего провайдер не сообщил, добирается из каталога [models.dev](https://models.dev) — такие модели
помечаются `из каталога` (в подсказке видно, какие именно поля и сколько источников их подтвердили).
Если источники расходятся, поле остаётся пустым с пометкой `спорно`: пустое поле честнее
выдуманного. Заявленное самим провайдером не перезаписывается никогда, даже если каталог
утверждает обратное — провайдер знает про свой шлюз больше. Цены не переносятся вообще:
155 моделей из каталога бесплатны у одного провайдера и платны у другого.

### Проверка боем: что означают пометки

Кнопка «⚡ Проверить все» шлёт по одному настоящему короткому запросу к каждой модели
(это реальные запросы, они могут стоить денег — поэтому спрашивается подтверждение).

| Пометка | Что значит | Что делать |
|---------|-----------|-----------|
| `✓` | Модель ответила | Ничего |
| `₽` | Ключ рабочий, но модель не входит в тариф | Пополнить баланс или убрать модель из списка |
| `↻` | Шлюз отклонил запрос временно (403 с пустым ответом) | Ничего: почти всегда проходит со второй попытки, она делается автоматически |
| `✕` | Модель действительно не отвечает | Проверить ID модели или удалить её |
| нет пометки | Не проверялась | — |

Различать их важно. Ключ, отвергнутый по-настоящему, — это 401 с текстом ошибки; пустой 403
у того же ключа означает временную блокировку шлюза. На живом шлюзе такое случалось примерно
в одном запросе из шести, и без этого различия три рабочие модели выглядели бы сломанными.
То же с таймаутами: две модели отвечали за ~4.6 c примерно через раз, а иначе молчали 20 c —
поэтому запрос, который вообще не дошёл, повторяется один раз, а полученный HTTP-ответ
(404, 429, отказ по тарифу) не повторяется никогда: ответ уже есть, а повтор просто съест лимит.

## Как это устроено

| Файл | Назначение |
|------|-----------|
| `server.mjs` | Node HTTP-сервер + API (слушает только 127.0.0.1) |
| `public/` | GUI (HTML/CSS/JS) |
| `src/jsonc-edit.mjs` | текстовый патчер JSONC: правит файл по месту, сохраняя комментарии и раскладку |
| `src/paths.mjs` | единственный источник путей + атомарная запись, хеши |
| `src/formats.mjs` | маппинг API-формат → npm-пакет opencode, поля схемы, кодирование ключей |
| `src/presets.mjs` | готовые провайдеры для мастера (Base URL, формат, имя env-переменной) + определение формата по URL |
| `src/opencode.mjs` | план → предпросмотр → запись `opencode.jsonc`, переименование/удаление, проверка хеша |
| `src/diff.mjs` | построчный diff + маскирование ключей в предпросмотре |
| `src/assets.mjs` | откуда берётся статика: `public/` в dev, SEA-ассеты в `.exe` |
| `src/targets.mjs` | манифесты + инструкции для Kilo/Cline/Roo и др. |
| `src/rescue.mjs` | бэкапы, восстановление, валидация, проверка соединения, разбор ответов провайдера |
| `src/batch.mjs` | пакетная проверка боем: параллелизм, паузы, backoff при 429, повтор недошедших запросов |
| `src/catalog.mjs` | каталог models.dev: загрузка, сверка источников, заполнение пробелов (без цен) |
| `src/proxy.mjs` | HTTP(S)-прокси для всех проб + ограничение размера ответа |
| `build-sea.mjs` | сборка `dist/provider-studio.exe` |
| `verify.mjs` | рантайм-проверка API на временном конфиге |
| `verify-batch.mjs` | проверка пакетного режима: троттлинг, стоп-условия, повторы |
| `verify-catalog.mjs` | проверка каталога: согласие источников, приоритет данных провайдера |
| `verify-ui.mjs` | сверка `index.html` ↔ `app.js` ↔ `style.css` + что все роуты достижимы из UI |
| `verify-sea.mjs` | проверка собранного `.exe` (пропускается, если сборки нет) |
| `data/providers.json` | локальное хранилище провайдеров (без ключей, вне git) |
| `data/backups/` | авто-бэкапы конфига (вне git) |

Хранилище и бэкапы лежат в пользовательской папке данных (`%LOCALAPPDATA%\provider-studio`,
переопределяется через `PS_DATA_DIR`), а не рядом с исходниками: упакованный `.exe`
может лежать в каталоге только для чтения.

## Важно про Kilo / Cline / Roo

Конфиг этих VS Code-расширений хранится в их внутреннем хранилище (`state.vscdb`),
формат нестабилен и зависит от версии. **Напрямую в него писать безопасно нельзя** —
можно сломать расширение. Поэтому утилита для них:
- заполняет ровно те поля, что есть в их UI (Name / Base URL / API key / API format),
- и отдаёт готовый JSON на копирование — вставляется через «Add provider».

## env var для ключа (режим по умолчанию)

Галочка «$ENV» включена изначально. В конфиг opencode вместо ключа пишется ссылка
`{env:BAI_API_KEY}` (именно этот синтаксис понимает opencode — `$BAI_API_KEY` он
подставлять не умеет и отправил бы строку как есть), а имя переменной попадает в `env`.

Установить саму переменную нужно один раз. Проще всего — кнопкой **«Задать
сейчас»**, которая появляется рядом с именем переменной, когда она не задана:
утилита возьмёт ключ из поля формы и выполнит `setx` сама. Значение уходит на
локальный сервер один раз и не возвращается обратно — в ответе только длина и
область видимости.

Либо вручную:

```powershell
setx BAI_API_KEY "твой-ключ"
```

После этого перезапусти терминал и opencode. Ключ остаётся вне конфига.

Установка возможна только в область **текущего пользователя**: машинная область
требует прав администратора, а ключ принадлежит пользователю, не машине. В
Linux/macOS кнопка не пишет ничего сама (нет однозначного файла профиля) — она
выдаёт готовую строку `export ...` для вставки в свой профиль.

**Поле «API key» в режиме `$ENV` не сохраняется.** В конфиг идёт только ссылка
`{env:ИМЯ}`; введённый в поле ключ отбрасывается. Если при этом переменная не
задана, утилита показывает предупреждение и требует подтверждения перед записью —
раньше запись просто проходила и отчитывалась «✓ Применено», а провайдер потом
отвечал 401.

Под именем переменной сразу показано, задана ли она, и в каком виде:

| Что показано | Значит |
|--------------|--------|
| `✓ ИМЯ задана (N симв., процесс)` | всё в порядке |
| `⚠ ИМЯ задана (N симв., пользователь)` | переменная есть в системе, но уже открытые терминалы её не видят — opencode нужно запускать из **нового** окна |
| `⚠ ИМЯ не задана` | opencode отправит пустой ключ и получит 401 |

Переменная ищется не только в окружении самого Provider Studio, но и в постоянных
настройках Windows (`HKCU\Environment` и системные переменные) — то есть там, куда
пишет `setx`. Поэтому переменная, созданная **после** запуска утилиты, определяется
корректно, без перезапуска.

Если снять галочку, ключ будет записан в конфиг открытым текстом — утилита
спросит подтверждение.

### 401 «Missing or invalid bearer token»

Самая частая причина — не сама ошибка в конфиге, а незаданная переменная.
`{env:FOO}` при отсутствующей `FOO` подставляется **пустой строкой**: opencode
отправляет `Authorization: Bearer` без значения, провайдер отвечает 401, и это
читается как «неверный ключ», хотя ключа просто нет.

Кнопка «Диагностика» находит это явно:

```
✕ Провайдер «atessa»: переменная ATESSA_API_KEY не задана — opencode отправит
  пустой ключ и получит 401. Выполни setx ATESSA_API_KEY "<ключ>" и перезапусти терминал
```

Проверка соединения и «Обнаружить модели» в этом случае тоже не идут в сеть, а
сразу называют причину — иначе провайдер вернул бы 401 и увёл в сторону.

Два подводных камня `setx`:
- значение длиннее **1024 символов молча обрезается** (часть длинных токенов
  под это попадает) — утилита предупреждает о такой длине;
- новое значение видят только **заново открытые** терминалы.

## «Провайдер недоступен»: кто виноват

Раньше любая неудача пробы выглядела одинаково — красная строка «недоступен».
Из-за этого лежащий сервер выглядел как испорченный ключ, и пользователь шёл
перегенерировать токен, с которым всё было в порядке. Теперь причина
разделяется:

| Что показано | Где проблема |
|--------------|--------------|
| `✓ доступен` | всё в порядке |
| `⚠ ключ не принят` | ключ был отправлен, сервер ответил 401/403 — ключ неверный или истёк |
| `⚠ нет ключа` | сервер ответил 401/403, но запрос ушёл вообще без ключа — поле `apiKey` пустое либо `{env:VAR}` указывает на незаданную переменную |
| `✕ сервер недоступен` | таймаут / домен не разрешается / соединение отклонено — сторона провайдера |
| `✕ прокси` | запрос не вышел наружу: прокси не отвечает или требует авторизации (407) |

Важное следствие: ответ **401 означает, что сервер жив**. Такой провайдер
показывается жёлтым, а не зелёным и не красным — прежняя логика считала его
полностью работающим, потому что эндпоинт ответил.

В диагностике к причине добавляется расшифровка: `таймаут — сервер не ответил
вовремя, скорее всего он лежит или закрыт файрволом`.

Отдельно разделены «ключ отвергли» и «ключ не отправили». Оба случая дают 401,
но чинятся по-разному: в первом надо перевыпустить токен, во втором — заполнить
`apiKey` или задать переменную окружения. Раньше пустой ключ показывался как
«ключ не принят», и пользователь шёл менять токен, которого вообще не было.
Признак берётся не из текста ответа, а из того, ушёл ли в запросе заголовок
`Authorization`/`x-api-key`.

### Что бесплатно, а что нет

В списке моделей у каждой строки видна цена за 1M токенов или метка `free`.
Источник вердикта важнее самого вердикта, поэтому он отслеживается явно:

| Источник | Что значит |
|----------|------------|
| тариф (`access_tier`) | провайдер сам объявил модель бесплатной или платной — факт |
| цена (`pricing`) | цена пришла и равна нулю — факт |
| название (`free?`) | цен нет, но в id есть `:free` — догадка, помечается вопросом |
| `цена ?` | провайдер не отдаёт ни тарифа, ни цен — неизвестно |

Разница не косметическая. У одного из проверенных провайдеров 36 бесплатных
моделей из 102, но `:free` в названии есть лишь у 17 — фильтр по имени скрывал
бы больше половины. В обратную сторону: провайдер, отдающий только `id` и
`owned_by`, не даёт оснований называть модель бесплатной, поэтому она
показывается как «неизвестно», а не как `free`. Отсутствие цены (`null`) и
нулевая цена (`0`) — разные вещи, и в конфиг пишется только известная цена.

Единицы приводятся к одному виду: объявленный `unit` (`per_1m_tokens`,
`per_1k_tokens`, `per_token`) главнее, а если его нет — величина. У OpenRouter
цена идёт в долларах за один токен, у остальных обычно за миллион; без
нормализации одна и та же модель выглядела бы то в 10⁶ раз дороже, то дешевле.

**Лимитов по числу запросов здесь нет намеренно.** Проверенные провайдеры не
возвращают ни заголовков `x-ratelimit-*`, ни полей квоты в `/models` —
показывать было бы нечего, кроме выдуманного числа.

#### Бесплатные тарифы в пресетах

У пресетов со свободным доступом (OpenRouter, Groq, Google AI Studio, NVIDIA NIM,

Из живых рабочих конфигов добавлены Xkiro (шлюз, `https://api.xkiro.com/v1`) и
GoRouter (локальный роутер, `http://localhost:14747/v1`, ключ не нужен).
Адреса взяты из проверенного в деле конфига, а не из документации.
Cerebras) есть заметка с лимитами, ссылкой на документацию самого провайдера и
**датой проверки**. Дата стоит не для красоты: сторонние подборки бесплатных LLM
устаревают молча. Например, на 2026-08-29 Cerebras прямо отвечает «Is there a
permanently free tier? No» ($5 кредитов на 30 дней), хотя популярные подборки
всё ещё обещают миллион токенов в день — поэтому в пресете написано, что
постоянного бесплатного тарифа там нет.

GitHub Models в пресеты не добавлен намеренно: эндпоинт отвечает HTTP 410
`github_models_retirement_brownout`, то есть его больше нет.

Числовые лимиты берутся только со страниц самого провайдера. Там, где точные
цифры отдаются скриптом и в HTML их нет (Google, Groq), числа не приводятся
вместо того, чтобы быть выдуманными.

### Прокси и VPN

Node **не читает** `HTTP_PROXY`/`HTTPS_PROXY` сам по себе. Поэтому за
корпоративным прокси или VPN-клиентом любая проба раньше отваливалась по
таймауту, и утилита винила провайдера, хотя запрос вообще не покидал машину.

Теперь прокси берётся (в этом порядке) из:

1. `https_proxy` / `HTTPS_PROXY` — для `https://`-целей;
2. `http_proxy` / `HTTP_PROXY` — для `http://`;
3. `all_proxy` / `ALL_PROXY`;
4. системных настроек прокси Windows (`Internet Settings`) — там, куда пишет
   GUI, если переменные не заданы.

`NO_PROXY` уважается, включая формы `.example.com`, `*.example.com` и `*`.
Поддерживаются `http`/`https`-прокси с авторизацией (`user:pass@host:port`);
для `https`-целей открывается CONNECT-туннель. SOCKS **не** поддерживается —
такой прокси честно игнорируется, вместо того чтобы притворяться и зависать.

Локальные адреса (`127.0.0.1`, `localhost`, RFC1918) через прокси не идут
никогда: ollama, LM Studio и vLLM живут именно там, и туннелировать их —
гарантированная ошибка.

Актуальный прокси показывается строкой в панели диагностики, поэтому видно,
шли пробы напрямую или через туннель.

## Что не хранится на диске

- API-ключи **не** сохраняются в `data/providers.json` — только ссылка на переменную.
- `/api/envcheck` возвращает только факт наличия переменной, её длину и область
  (процесс / пользователь / система) — никогда значение.
- Значение переменной используется сервером только для исходящей проверки
  соединения и в ответ браузеру не попадает.
- «Скопировать JSON» и конфиги для Kilo/Cline/Roo подставляют placeholder вместо ключа.
- `data/providers.json` и `data/backups/` исключены из git через `.gitignore`.

## Доступ по сети

Сервер слушает только `127.0.0.1`: API без авторизации и умеет читать конфиг
opencode, поэтому доступ из локальной сети означал бы отдачу ключей любому в той
же сети. Дополнительно любой запрос с посторонним `Host` отбрасывается (защита от
DNS rebinding), а изменяющие запросы — ещё и при постороннем `Origin` /
`Sec-Fetch-Site` (защита от CSRF).

Открыть на все интерфейсы можно осознанно — при запуске выводится предупреждение:

```powershell
$env:PS_HOST="0.0.0.0"; npm start
```

npm run verify:exe    # собрать .exe и проверить именно его

| `verify-paths.mjs` | пути, атомарная запись, поведение при сбое |
| `verify-env.mjs` | разбор `{env:VAR}`, поиск переменной во всех областях Windows, реальный цикл `setx` → чтение → удаление, запись переменной и её ограничения |

## Известные ограничения

- «Проверить» считает ответы 401/403 достижимостью: сервер жив, но ключ не принят
  (в списке — жёлтая точка, не зелёная). Если ключ вообще не был отправлен, об
  этом говорится отдельно.
- Проверка `/models` не гарантирует, что чат заработает: ключ может не иметь
  доступа именно к этой модели, а квота — быть исчерпана. Это ловит только
  проверка боем — на последнем шаге мастера или кнопкой «⚡ Проверить все».
- Пакетная проверка тратит настоящие запросы и на платных провайдерах стоит
  денег; за раз проверяется не больше 200 моделей.
- Каталог models.dev не знает про шлюзы-агрегаторы: он сопоставляется только по
  id модели, поэтому у переименованных моделей пробелы останутся незаполненными.
  Это осознанно — лучше пусто, чем чужие характеристики.
- SOCKS-прокси не поддерживается (нужен другой handshake); такой прокси
  игнорируется, и проба идёт напрямую.
- При работе через прокси имя хоста разрешает сам прокси, поэтому локальная
  защита от DNS-rebinding в этом пути не применяется — блокировка адресов
  метаданных по имени и по собственному резолву остаётся.
- Установка переменной окружения из интерфейса работает только на Windows и
  только в области текущего пользователя; значения длиннее 1024 символов
  отклоняются, потому что `setx` молча их обрезает.
- Определить, задана ли переменная, наверняка можно только на Windows (читаются
  все постоянные области). На Linux/macOS видно лишь окружение самого процесса,
  поэтому отсутствие переменной там — предупреждение, а не ошибка: её может
  подставлять обёртка, которую утилита не видит.
- Проверка соединения по умолчанию **разрешает** loopback и локальную сеть — иначе
  ollama, LM Studio и vLLM было бы не проверить. Запросы к метаданным облака
  (`169.254.0.0/16`, `metadata.google.internal`) блокируются всегда. Полностью
  запретить локальные адреса: `PS_BLOCK_LOCAL_PROBE=1`.
- Kilo / Cline / Roo автоматически не патчатся — см. раздел выше.
- Собранный `.exe` под конкретную ОС и архитектуру: он содержит копию текущего
  `node`, кросс-сборки нет.
- Пути к конфигу рассчитаны в первую очередь на Windows (учитывается `XDG_CONFIG_HOME`).

## Несколько конфигов и откуда бэкап

- Переключатель конфига в шапке — настоящий: диагностика, проверка, бэкап,
  импорт и восстановление работают с выбранным файлом, а не с файлом по
  умолчанию. Хеш для защиты от concurrent-правок тоже берётся из него.
- Каждый бэкап помнит файл, из которого снят (видно в списке). Восстановление
  пишет в исходный файл, а не в тот, что открыт в интерфейсе.
- Путь к конфигу, пришедший по HTTP, принимается только если это известное
  место (кандидат из списка или `OPENCODE_CONFIG`). Чужой путь игнорируется —
  эндпоинты не работают читалкой/писалкой произвольных файлов.
- Откат («Отменить») отказывается работать, если файл изменился после
  откатываемой записи: молча затирать чужие правки нельзя, восстанови из
  бэкапа вручную.
- Русские названия провайдеров транслитерируются в ключ (`БайТест` →
  `baytest`), а не схлопываются все в один `provider`.
- Обновление моделей опрашивает провайдеров параллельно (до 3 одновременно),
  порядок в плане — как в конфиге.
- Самопроверка честно проверяет именно запись (право W_OK на файл или каталог),
  а не чтение.

## Умный аудит

Едет внутри каждой диагностики, отдельным запросом ходить не надо:

- один id модели у нескольких шлюзов — с пометкой, где дешевле;
- модель по умолчанию стоит не на самом дешёвом источнике — warn с кнопкой
  «Сделать основным» (та же защищённая запись через хеш, что везде);
- модели без limit/cost — opencode их угадывает, аудит показывает сколько;
- оценка гигиены: 100 − 10 за warn − 3 за info, формула зафиксирована
  в `src/smart-audit.mjs`.

Чистая статика, сети не касается — считается миллисекунды.

# Provider Studio

Красивый минималистичный GUI для добавления кастомных AI-провайдеров и моделей
в **opencode**, а также для **Kilo Code**, **Cline**, **Roo Code**, **ZCode**,
**DeepSeek Harness** и любых других harness-ов с поддержкой кастомных эндпоинтов.

Рантайм без зависимостей — чистый Node.js. `esbuild` и `postject` нужны только
для сборки `.exe` и стоят в `devDependencies`.

## Запуск

```powershell
cd provider-studio
npm start
```

Откроется браузер на `http://localhost:5173`. Двойным кликом — `start-provider-studio.cmd`.

> Если порт занят, сервер сам возьмёт следующий свободный (5174, 5175…).

## Сборка в один .exe

```powershell
npm install   # один раз — esbuild + postject
npm run build
```

Результат: `dist/provider-studio.exe` (~88 МБ — внутри целый Node-рантайм).
Файл самодостаточен: ни Node, ни папка `public/` рядом не нужны — GUI зашит
в бинарник как SEA-ассеты.

Как это работает и почему именно так:

- Формат single-executable принимает **только CommonJS**, а проект целиком на ESM,
  поэтому `server.mjs` сначала собирается в CJS через `esbuild`.
- Бандлер превращает `import.meta.url` в `{}`, так что `fileURLToPath(import.meta.url)`
  молча стал бы падать. Поэтому корень статики ищется через `argv[1]`/`execPath`
  (`src/assets.mjs`), а сборка **проверяет**, что в бандле не осталось `import.meta`.
- `postject` не читает пути с не-ASCII символами (а репозиторий вполне может лежать
  в папке с кириллицей), поэтому инъекция всегда делается в ASCII-каталоге в `%TEMP%`,
  а готовый файл копируется обратно.
- Последний шаг билда — запуск самого `.exe` с самопроверкой: он отдаёт `/`, `/app.js`,
  `/style.css`, `/api/state` и проверяет, что обход каталога по-прежнему блокируется.
  Сборка падает, если UI недостижим, — «собралось» значит «работает».

## С чего начать (если делаешь это впервые)

Нажми **«Мастер настройки»** в левом нижнем углу — 4 шага:

1. **Сервис.** Выбираешь сервис из 12 актуальных карточек (OpenRouter, Google
   AI Studio, DeepSeek, Anthropic, OpenAI, Groq, Together, Mistral, Z.ai,
   Ollama, LM Studio) — Base URL, формат API и имя переменной окружения
   подставляются сами. Base URL — единственное поле, которое невозможно
   угадать, а ошибка в нём проявляется только позже, уже внутри opencode, как
   404 на каждом запросе. Есть вариант «Другой (вручную)» для любого
   совместимого эндпоинта. Нишевые Xkiro, NVIDIA NIM и Cerebras скрыты из
   мастера, но остаются в данных для импорта, discovery и «Халявы».
2. **Ключ.** Вставляешь API-ключ; для локальных (Ollama, LM Studio) он не нужен.
   Рядом сразу видно, задана ли нужная переменная окружения, и готовую команду
   `setx`, если нет.
3. **Модели.** Список подтягивается с сервера; отмечаешь нужные. Если сервер не
   отдаёт `/models`, показывается встроенный список пресета.
4. **Запись.** Итоговая сводка, затем обычный diff — на диск ничего не идёт,
   пока не подтвердишь.

Мастер не пишет в файл напрямую: он заполняет основную форму и уходит в тот же
путь «diff → подтверждение → запись», что и ручной режим.

## Что делает

- Заполняешь **Название / Base URL / API-ключ / Формат API** — как в UI Kilo Code.
  Формат API определяется по Base URL автоматически, пока не выберешь вручную.
- Добавляешь модели: **Model ID, контекст, макс. выход, типы входа/выхода, reasoning, tools**.
- Выбираешь куда добавить:
  - **opencode** — пишет напрямую в `~/.config/opencode/opencode.jsonc`: блок провайдера
    с `npm` (пакет AI SDK), `name` (отображаемое имя), `options.baseURL`, `options.apiKey`
    и модели с `modalities` / `limit` / `attachment` / `reasoning` / `tool_call`.
    Модель по умолчанию выбирается в выпадающем списке рядом с «Применить».
  - **Kilo Code** — пишет в `~/.config/kilo/kilo.json(c)` (та же схема, что у opencode),
    сохраняя комментарии и посторонние поля.
  - **WorkBuddy AI** — пишет/мержит `~/.codebuddy/models.json`; ключ остаётся ссылкой
    `${ENV_VAR}`, URL — полный `/chat/completions`.
  - **OpenChamber** — отдельный конфиг не нужен: он читает провайдеров OpenCode.
  - **Cline / Roo / Verdent / Qoder / Kiro / Generic** — генерирует конфиг на копирование
    и пошаговую инструкцию (Qoder — Settings → Models → Custom; Kiro — только сетевой
    прокси, custom endpoint не поддерживает).
- «Скопировать JSON» — кладёт манифест в буфер, ключ заменяется на placeholder.

## Защита от ошибок (то, что избавит от проблем)

| Возможность | Как включить | Что делает |
|-------------|--------------|-----------|
| **Комментарии и форматирование сохраняются** | всегда | Конфиг правится текстовым патчем по месту, а не перезаписывается как JSON: комментарии, отступы и однострочные `{ … }` остаются как были |
| **Показ diff до записи** | кнопка «Показать diff» | Показывает построчно, что именно изменится в файле. Пока не нажмёшь «Записать в файл», на диск ничего не идёт |
| **Защита от конкурентной правки** | всегда | Запись отправляется вместе с хешем прочитанного файла. Если файл успел измениться (руками или другим инструментом), запись отклоняется с 409, а не затирает чужие изменения |
| **Удаление провайдера** | кнопка с корзиной в списке | Удаляет по-настоящему: сначала показывает diff, потом убирает блок из `opencode.jsonc` (с бэкапом и откатом) и из списка Studio. Ключ берётся ровно тот, что в конфиге (`my_provider` и `dot.name` не превращаются в slug). Переназначает `model`/`small_model`, если они ссылались на удаляемый; переменные окружения, которые остались бы без ссылок, перечисляет в подтверждении, но не удаляет сам. Плагин пула убирается в корзину данных и возвращается вместе с откатом. Синхронно вычищает зомби-конфиги из Kilo Code и WorkBuddy |
| **Переименование ключа** | кнопка с карандашом в списке | Переименовывает ключ провайдера, сохраняя сам блок и его комментарии. Точный ключ тоже сохраняется: `my_provider` правится как `my_provider`, а не как его slug |
| **Повторное включение** | любое сохранение провайдера | Если ключ лежит в `disabled_providers`, запись убирает его оттуда — иначе opencode продолжил бы прятать провайдера, а Studio отчиталась бы об успехе. Остальные записи списка не трогаются |
| **Синхронное удаление зомби-конфигов** | при удалении провайдера | Автоматически удаляет связанные конфигурации и модели из Kilo Code (`~/.config/kilo/kilo.json(c)`) и WorkBuddy AI (`~/.codebuddy/models.json`). В Kilo переназначает default-модель, если она ссылалась на удалённого провайдера |
| **Очистка переменных-призраков** | кнопка «Удалить все сироты» в Env-аудите | Находит брошенные ключи в `HKCU\Environment` (не привязанные к активным провайдерам или шардам) через эндпоинт `/api/env-clean-orphans` и безопасно удаляет их из реестра |
| **Защита системных переменных** | всегда | `PATH`, `TEMP`, `TMP`, `COMSPEC`, `SYSTEMROOT`, `WINDIR`, `USERPROFILE`, `HOMEDRIVE` защищены от перезаписи и удаления при любых операциях с окружением |
| **Поддержка токенов > 1024 символов** | автоматически | Обходит жесткое ограничение Windows `setx` (молча обрезающее значения длиннее 1024 символов), генерируя безопасную команду PowerShell через `[Environment]::SetEnvironmentVariable` |
| **Защита от блокировок NTFS** | всегда | Атомарная запись (`writeFileAtomic`) при возникновении `EBUSY`/`EPERM`/`EACCES` на `renameSync` выполняет до 8 попыток с экспоненциальным backoff (25–200 мс) и рандомным джиттером |
| **Плагины ротации OpenCode V2** | при сохранении пула ключей | Генерирует плагины в виде полноценных каталогов `plugins/keypool-<slug>/` с `package.json` и `index.mjs` (экспорт `{ id, setup }`), полностью удовлетворяя требованию OpenCode V2 |
| **Мульти-заголовки авторизации** | автоматически в пуле | Поддерживает и переключает заголовки под любой шлюз: `x-goog-api-key` (Google), `api-key` (Azure), `x-api-key` (Anthropic) и `Authorization: Bearer` (OpenAI и др.) |
| **Суточные лимиты vs RPM** | в пуле ключей и диагностике | Тонко распознаёт исчерпание суточных квот (Groq RPD/TPD, Cerebras, OpenRouter stealth — вывод ключа из ротации) в отличие от минутного троттлинга RPM (Gemini 15 RPM — кулдаун 60с) |
| **Выбор файла конфига** | список в шапке | Если конфигов несколько (глобальный/проектный), выбираешь, в какой писать |
| **Авто-бэкап перед изменением** | всегда | Перед любым изменением `opencode.jsonc` снимается снапшот в `data/backups/` |
| **Ручной бэкап** | кнопка «Бэкап» | Создать снапшот прямо сейчас |
| **Восстановление** | «Восстановить» у любого бэкапа | Возвращает файл байт-в-байт, вместе с комментариями (перед этим текущий тоже бэкапится) |
| **Валидация** | кнопка «Проверить конфиг» | Ищет неизвестные поля провайдера/модели, `apiKey`/`baseURL` не на своём уровне, пакет в поле `name` вместо `npm`, ключи вида `$VAR`, незаданные переменные окружения, неполный `limit`/`cost`, `output` больше `context`, отсутствие `attachment` у вижн-моделей, битую модель по умолчанию, некорректный `options.timeout`, мусор в массиве `env`, два провайдера на один Base URL, отсутствие ключа и env у публичного провайдера |
| **Халява** | кнопка «Халява» | Ежедневный дайджест с публичного борда Ailyre: какие провайдеры прямо сейчас раздают (промо, триалы, студенческие тарифы) и какие новости влияют на доступ. Кэш на 6 часов, при недоступности сети — вчерашний кэш с пометкой, а не ошибка. Только чтение: кнопок «забрать» нет, у каждой записи ссылка на источник |
| **Только бесплатные** | «Диагностика» → «Обновить модели» | В плане обновления у новых моделей видна метка `free` (по заявленной провайдером нулевой цене, а не по названию), галочка оставляет к записи только бесплатные. Неизвестная цена бесплатной не считается |
| **Проверка соединения** | кнопка «Проверить» | Пробует достучаться до Base URL и подсказывает, если ключ/URL кривой. Ссылка `{env:VAR}` разворачивается так же, как это сделает opencode, а формат API определяет заголовок (`Authorization` или `x-api-key`). Это проверка `/models`, а не генерации: 200 здесь не значит, что выбранная модель ответит, — для этого есть ⚡ у модели и «Проверить все» |
| **Редактирование существующих** | клик по провайдеру в списке | Загружает провайдера/модели в форму, меняешь и жмёшь «Применить» |
| **Импорт из opencode** | «Импортировать из opencode» | Подтягивает провайдеров из конфига, чтобы их можно было править |
| **Обнаружение моделей** | «Обнаружить» в шапке списка моделей | Автоматически подтягивает список моделей с сервера (`/models`) по Base URL + ключу |
| **Фильтры моделей** | в окне обнаружения и в мастере | Поиск + фильтры «Бесплатные», «С вижном», «С reasoning» |
| **Цена и признак «бесплатно»** | в списках моделей | У каждой модели видно `$вход / $выход` за 1M токенов либо метка `free`. Берётся из ответа провайдера (`access_tier`, `pricing`), а не угадывается по названию; единицы нормализуются (per-token у OpenRouter и per-1M у других приводятся к одному виду). Найденные цены попадают в конфиг как `cost` — одинаково и через «Обнаружить модели», и через мастер |
| **Диагностика** | «Диагностика» | Проверяет всё сразу: конфиг + доступность каждого провайдера + модель по умолчанию. Различает «сервер лёг», «ключ не принят» и «ключ не отправлен» |
| **Автоисправление** | «Диагностика» → «Исправить автоматически» | Чинит всё однозначное: мусорные поля, ключ/адрес не на своём уровне, `$VAR` → `{env:VAR}`, открытый ключ → ссылка на переменную (значение при применении записывается в переменную само — на Linux/macOS даётся готовая команда — а из файла стирается; копия остаётся в бэкапе), неполные `limit`/`cost`, левые `modalities`/`status`, висячую модель по умолчанию. Сначала показывает обычный diff, пишет только после подтверждения, перед записью — бэкап. Что требует человека (пустой список моделей) — перечисляет отдельно |
| **Обновление моделей** | «Диагностика» → «Обновить модели» | Сверяет конфиг с живым `/models` каждого провайдера: показывает, что добавилось, а с галочкой — и что пропало с сервера. Существующие записи не перезаписываются, ручные правки сохраняются. Галочка «дозаполнить характеристики» дописывает существующим моделям недостающие лимиты, цены и вижн (только заявленное провайдером, только в пустые поля). Запись — после подтверждения, с бэкапом |
| **Самопроверка** | «Диагностика» → «Самопроверка» | Проверяет сам инструмент: версия Node, запись в каталоги данных и бэкапов, чтение и разбор конфига, прокси, доступность справочника models.dev. Недоступный каталог — предупреждение, а не приговор: без него инструмент работает |
| **Откат последней правки** | кнопка «Отменить» | Возвращает конфиг к состоянию до последней записи (применение, автофикс, обновление моделей, смена default, переименование, удаление, восстановление). Перед откатом текущий файл тоже бэкапится, так что ошибочный откат сам откатываем из списка бэкапов. Одноуровневый по design: после отката откатывать уже нечего |
| **Наблюдение за файлом** | автоматически | Раз в 5 секунд сверяет хеш конфига на диске. Если форма пустая — молча подхватывает новый хеш, если есть несохранённые правки — показывает жёлтый баннер с кнопкой «Обновить», чтобы следующая запись не умерла с 409 |
| **Проверка одной модели** | кнопка с молнией в строке модели | Отправляет один пробный запрос (~16 токенов) к конкретной модели без пакетной очереди. Результат — та же метка `✓`/`₽`/`↻`/`✕`, что и у «Проверить все» |
| **Отчёт для issue** | «Диагностика» → «Скопировать отчёт» | Копирует сводку последнего прогона диагностики в markdown: провайдеры, конфиг-проблемы, путь, default-модель. Ключи вида `sk-…`, Bearer и значения `apiKey` затираются, ссылки `{env:…}` сохраняются — без них отчёт не объяснит проблему с переменной |
| **Проверка боем** | шаг 4 мастера | Отправляет один реальный запрос выбранной модели (16 токенов — дешевле шлюзы отвергают). «✓ Применено» означает лишь «файл записан» — а это проверяет, что связка действительно работает. Формат `openai-responses` пробуется через `/responses` со своим телом, а не через `/chat/completions` |
| **Проверка всех моделей сразу** | «Проверить все» | Прогоняет по одному настоящему запросу к каждой модели, по 3 параллельно с паузой между ними. При серии 429 пауза удваивается, а потом проверка останавливается, чтобы не выжечь лимит. Результат помечается прямо у модели: `✓` работает, `₽` не входит в тариф, `↻` шлюз отклонил временно, `✕` не отвечает. Модели, до которых не дошли, честно перечисляются как непроверенные, а не выдаются за сломанные |
| **Пул ключей** | поле «Пул ключей», кнопки «Проверить пул» / «Записать пул в env» | Несколько ключей (по одному на строке) разворачиваются в шарды провайдера с переменными BASE, BASE_2… и плагином ротации keypool-<slug>.mjs: 401/402/429/5xx переключают запрос на следующий живой ключ, неверный id модели и битый конфиг — нет. «Проверить пул» шлёт по одному запросу с каждого ключа (метки те же: ✓/₽/↻/✕) и показывает баланс там, где провайдер его отдаёт (OpenRouter); у остальных вердикт даёт живая проба, а не выдуманная цифра |
| **Характеристики из models.dev** | автоматически при обнаружении | Пробелы в контексте, лимите выхода, вижне и reasoning заполняются из открытого каталога models.dev (7435 моделей). Заполняется только то, чего провайдер не сообщил сам, и только когда источники согласны между собой — иначе стоит пометка «спорно». **Цены оттуда не берутся никогда**: одна и та же модель у одного провайдера бесплатна, у другого платная |
| **Смена модели по умолчанию** | «Диагностика» → «Сделать основной» | Если `model` указывает на недоступного провайдера, а рабочий уже настроен — переключает одной кнопкой, меняя ровно одну строку конфига. Сначала предлагаются провайдеры без проблем; те, у кого не принят или не задан ключ, идут ниже и с пометкой, а если здоровых нет вовсе — об этом говорится прямо, а не молча предлагается сломанный |
| **Установка переменной окружения** | «Задать сейчас» у имени переменной | Выполняет `setx` за тебя, ключом из формы. Раньше здесь была команда, которую надо было скопировать вручную — именно на этом шаге настройка обычно и застревала |
| **Индикатор доступности** | точка в списке слева | Зелёная — отвечает, жёлтая — сервер жив, но ключ не принят или не отправлен, красная — недоступен, серая — ещё не проверялся |
| **Раскладка в две колонки** | всегда | Слева редактор, справа — обзор с умными маршрутами, результаты и бэкапы. Правая колонка имеет минимум 430px и растягивается вместе с окном; ниже 1300px колонки схлопываются в одну. На ширине от 1700px карточка редактора сама делится на «подключение» и «модели/таргеты/действия». На 1920×919 и 1700×1000 всё помещается без вертикального скролла |
| **Вкладки правой панели** | «Обзор» / «Результаты» / «Бэкапы» | Новые отчёты больше не добавляются бесконечным стеком: активная вкладка одна, вкладки остаются на месте при прокрутке, а результаты и бэкапы не сдвигают страницу. У «Результатов» есть точка непрочитанного, у «Бэкапов» — счётчик |
| **Умные маршруты** | «Обзор» | Ранжирует уже настроенные модели по цене, контексту, reasoning, tools, vision и последней диагностике: основной, быстрый, с картинками, резерв. Кнопка «Сделать основной» меняет только top-level `model` — с бэкапом и откатом |
| **Умные раскрытия** | форма и список моделей | «Пул ключей и формат API» — один свёрнутый блок с текущим форматом и числом ключей в заголовке; сам открывается для нестандартного формата или непустого пула. Список моделей показывает первые 4, остальные — за кнопкой «Показать все (N)» |
| **Статус сохранённого ключа** | после загрузки провайдера | Если ключ хранится в env, поле намеренно пустое: в нём написано «Сохранён в ИМЯ — введи новый ключ», а зелёная подсказка объясняет, что секрет не потерян и не возвращается в браузер. Глаз показывает только вновь введённый ключ |
| **Работа через прокси** | автоматически | Пробы уважают `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY` и системный прокси Windows. Локальные провайдеры (`127.0.0.1`, RFC1918) через прокси не гоняются |
| **Мастер настройки** | «Мастер настройки» | 4 шага: **Сервис → Ключ → Модели → Запись**. Base URL и формат API подставляются из пресета; в сетке 12 актуальных сервисов. На телефоне футер с «Назад/Далее» закреплён и не уезжает за экран |
| **Ключ-превью** | под полем «Название» | Показывает, в какой ключ конфига превратится имя, и предупреждает, если такой ключ уже занят другим провайдером — запись тогда обновит его, а не создаст новый |
| **Фильтр пресетов** | шаг 1 мастера | Строка поиска по названию, подсказке, адресу и id — при 12 карточках листать всё не нужно |
| **Проверка переменной окружения** | автоматически | Рядом с именем переменной видно, задана ли она и в какой области. `{env:FOO}` при незаданной `FOO` авторизуется пустой строкой — это заметно только по 401, поэтому запись с незаданной переменной требует подтверждения |
| **Поиск по провайдерам** | появляется от 6 провайдеров | Фильтр списка в сайдбаре, `/` ставит курсор в поиск |
| **Горячие клавиши** | всегда | `Ctrl+S` — применить, `Ctrl+D` — показать diff, `/` — поиск, `Esc` — закрыть окно |
| **Запоминание выбранного конфига** | всегда | Выбранный в шапке файл восстанавливается при следующем запуске — но только если он всё ещё есть в списке |

Хранилище: `data/backups/` хранит до 30 последних бэкапов, старые удаляются автоматически.

### Обнаружение моделей

Кнопка «Обнаружить» запрашивает `/models` у указанного Base URL и строит список моделей.
Способности (vision / reasoning / free) подбираются автоматически по имени модели и метаданным
(где провайдер их отдаёт). В окне можно отфильтровать по типу и отметить галочками нужные —
они попадут в список моделей провайдера.

Чего провайдер не сообщил, добирается из каталога [models.dev](https://models.dev) — такие модели
помечаются `из каталога` (в подсказке видно, какие именно поля и сколько источников их подтвердили).
Если источники расходятся, поле остаётся пустым с пометкой `спорно`: пустое поле честнее
выдуманного. Заявленное самим провайдером не перезаписывается никогда, даже если каталог
утверждает обратное — провайдер знает про свой шлюз больше. Цены не переносятся вообще:
155 моделей из каталога бесплатны у одного провайдера и платны у другого.

### Проверка боем: что означают пометки

Кнопка «Проверить все» шлёт по одному настоящему короткому запросу к каждой модели
(это реальные запросы, они могут стоить денег — поэтому спрашивается подтверждение).

| Пометка | Что значит | Что делать |
|---------|-----------|-----------|
| `✓` | Модель ответила | Ничего |
| `₽` | Ключ рабочий, но модель не входит в тариф | Пополнить баланс или убрать модель из списка |
| `⚠` | Модель недоступна в твоём регионе (например stealth-модели OpenRouter) | Ключ рабочий: нужен прокси/VPN в поддерживаемой стране или другая модель |
| `↻` | Шлюз отклонил запрос временно (403 с пустым ответом или WAF) | Ничего: почти всегда проходит со второй попытки, она делается автоматически |
| `✕` | Модель действительно не отвечает | Проверить ID модели или удалить её |
| нет пометки | Не проверялась | — |

Различать их важно. Ключ, отвергнутый по-настоящему, — это 401 с текстом ошибки; пустой 403
у того же ключа означает временную блокировку шлюза. На живом шлюзе такое случалось примерно
в одном запросе из шести, и без этого различия три рабочие модели выглядели бы сломанными.
То же с таймаутами: две модели отвечали за ~4.6 c примерно через раз, а иначе молчали 20 c —
поэтому запрос, который вообще не дошёл, повторяется один раз, а полученный HTTP-ответ
(404, 429, отказ по тарифу) не повторяется никогда: ответ уже есть, а повтор просто съест лимит.

### Пул ключей с автопереключением (OpenCode V2)

Поле «Пул ключей» живёт в раскрывающемся блоке «Пул ключей и формат API» и
принимает запасные ключи — по одному на строке. В заголовке блока сразу видно
текущий формат и число ключей. Пустое поле означает обычный одиночный режим,
ничего не меняется.

Что происходит при применении пула:

- **Шардирование провайдера:** провайдер разворачивается в шарды: первый сохраняет имя и переменную (например `DEEPSEEK_API_KEY`), остальные — `имя-2`, `имя-3`… с `DEEPSEEK_API_KEY_2`, `…_3`… Модели у всех шардов идентичны, а модель по умолчанию указывает на первый шард.
- **Архитектура плагина OpenCode V2:** рядом с конфигом в каталоге `plugins/keypool-<slug>/` создаётся полноценный пакет плагина:
  - `package.json` (`name: "keypool-<slug>"`, `version: "1.0.0"`, `type: "module"`, `main: "index.mjs"`);
  - `index.mjs` с нативным экспортом плагина OpenCode V2:
    ```javascript
    export default {
      id: "keypool-<slug>",
      setup: async () => { ... }
    };
    ```
  - Путь к каталогу плагина регистрируется в массиве `plugin` корневого конфига: `["<директория>/plugins/keypool-<slug>"]`. Это полностью решает требование OpenCode V2, где плагинами могут быть только каталоги, и предотвращает ошибку рантайма `configured plugin path must be a directory`.
- **Мульти-заголовочная авторизация:** плагин автоматически распознаёт тип провайдера и выставляет требуемые заголовки при ротации:
  - **Google Gemini / AI Studio:** заголовок `x-goog-api-key: <ключ>`;
  - **Azure OpenAI:** заголовок `api-key: <ключ>`;
  - **Anthropic:** заголовок `x-api-key: <ключ>` и `anthropic-version: 2023-06-01`;
  - **OpenAI-совместимые шлюзы (OpenRouter, Groq, Cerebras, DeepSeek и др.):** `Authorization: Bearer <ключ>`.
  Запросы с любым из этих заголовков корректно перехватываются и ротируются.
- **Тонкое распознавание суточных лимитов vs RPM-троттлинга:**
  - **Суточные лимиты (RPD/TPD):** исчерпание дневной квоты (Groq `requests per day`, `tokens per day`, Cerebras `tokens per day limit exceeded`, OpenRouter `free-models-per-day-stealth`, паттерны `daily limit`, `usage limit reached`) помечает ключ как мёртвый (`dead: true`) и выводит его из ротации до перезапуска, избавляя от бессмысленных повторов.
  - **Минутный троттлинг (RPM):** минутные ограничения (Gemini 15 RPM с ответом `Resource has been exhausted (e.g. check quota)` или классический HTTP 429) распознаются как временные: ключ **не** удаляется из пула, а уходит на кулдаун в 60 секунд (с экспоненциальным ростом до 300 с при повторных ошибках) и после истечения паузы снова доступен для работы.
  - **HTTP 401:** неверный или отозванный ключ — выводится из ротации (`dead: true`).
  - **HTTP 402:** исчерпание депозита/баланса (`Payment Required`) — ключ помечается мёртвым (`dead: true`).
  - **HTTP 403 пустой / WAF:** временная блокировка шлюза — кулдаун 10 секунд.
  - **HTTP 403 Region Block:** модель недоступна для страны запроса (`not available in your region`, `geo restrict`) — плагин **не** крутит ключи по кругу, так как все ключи из этого региона получат идентичный отказ.
  - **HTTP 404 Account Capacity:** ответ `not supported by any configured account in this group` означает нехватку мощностей на конкретном аккаунте шлюза — запрос успешно переключается на следующий ключ пула.
  - **HTTP 5xx / Сетевой сбой:** временная ошибка сервера — кулдаун 30 секунд.
- **Поддержка реестра Windows без перезапуска:** плагин в рантайме умеет опрашивать `HKCU\Environment` через `reg query`, поэтому переменные окружения, добавленные через `setx` после старта OpenCode, подхватываются без перезапуска терминала.
- **Изоляция пулов и точные URL:** каждый пул защищён уникальным guard-флагом `globalThis.__psKeypoolPatched_<slug>`, что позволяет нескольким разным провайдерам иметь собственные независимые пулы ключей. Сопоставление URL выполняется строго по границе пути (`url === POOL_BASE || url.startsWith(POOL_BASE + "/") || url.startsWith(POOL_BASE + "?")`), предотвращая случайную подмену авторизации у провайдеров на том же домене (например, `/v1` и `/v10`).
- **Синхронная запись и откат:** кнопка «Записать пул в env» выполняет установку всех переменных пула (до 20 ключей). При удалении провайдера плагин и все связанные шарды синхронно удаляются из конфига и файловой системы (с возможностью полного отката через резервную копию).

«Проверить пул» отправляет по одному настоящему запросу с каждого ключа (нужен id модели — берётся первая из списка) и показывает построчный вердикт теми же метками `✓`/`₽`/`↻`/`✕`. Баланс цифрой показывает только там, где провайдер отдаёт его через API (OpenRouter через `GET /api/v1/key`); у остальных провайдеров вердикт даёт живая проба.

Ограничения: ротация живёт в процессе opencode (перезапусти его после применения), кулдауны и мёртвые ключи сбрасываются при перезапуске службы, повтор запроса со стриминговым телом невозможен — тогда возвращается первый ответ без повтора.

## Две схемы конфига (V1 `provider` и V2 `providers`)

OpenCode понимает оба вида, но они **не взаимозаменяемы**:

- V1: `"provider": { "<key>": { "npm", "options": { "baseURL", "apiKey" }, "models" } }`;
- V2: `"providers": { "<key>": { "package", "settings": { "baseURL", "apiKey" }, "models" } }`.

Блок `provider` в V2 считается легаси: `capabilities` внутри него **игнорируется**
(проверено: `tools:false` не применяется), а `reasoning` и `attachment` V2
выбрасывает с предупреждением «omitted unsupported legacy setting». Vision и
tools там ещё работают — они выводятся из `modalities`, — а вот `reasoning.effort`
объявить нельзя: он есть только в нативном `providers`. Если в файле есть оба
ключа, V2 берёт `providers` и `provider` не сливает с ним.

Поэтому студия читает и пишет **ту схему, которая уже лежит в файле**:

- чтение: `src/schema.mjs` строит из `providers` V1-вид (`package`→`npm`,
  `settings`→`options`, `capabilities`→`modalities`/`reasoning`/`tool_call`) и
  вешает его неenumerable-свойством `provider`, так что все существующие
  читатели работают без изменений, а в JSON и на диск дубль не попадает;
- запись: правки, собранные в V1-виде, применяются к V1-копии блока и
  записываются обратно **одним** `set` в `providers.<key>`; `effort`, `toggle` и
  `budget` у `capabilities.reasoning` переносятся как есть (в форме для них нет
  полей, и терять их при каждом сохранении нельзя);
- сохранение без изменений не переписывает блок: структурное сравнение
  отменяет запись, поэтому no-op не даёт diff и не ломает раскладку;
- пустой `providers: {}` остаётся V2: он появляется после удаления последнего
  V2-провайдера, и трактовать его как V1 значило бы записать следующий блок в
  `provider`, который V2 не читает;
- если в файле есть оба ключа, активна карта `providers`, а легаси-блок
  сохраняется отдельно и показывается предупреждением `mixed-provider-maps` в
  «Проверить конфиг» — студия его не перезаписывает и не считает живым.

Миграция живого конфига на V2 (с бэкапом) добавляет `settings`,
`package: "@ai-sdk/openai-compatible"` и
`capabilities.reasoning: { "supported": true, "effort": [...] }`:

```jsonc
"providers": {
  "lunaroute": {
    "name": "lunaroute",
    "env": ["LUNAROUTE_API_KEY"],
    "package": "@ai-sdk/openai-compatible",
    "settings": {
      "baseURL": "https://gw.lunaroute.com/v1",
      "apiKey": "{env:LUNAROUTE_API_KEY}"
    },
    "models": {
      "muse-spark-open": {
        "capabilities": {
          "tools": true,
          "input": ["text", "image"],
          "output": ["text"],
          "reasoning": { "supported": true, "effort": ["minimal", "low", "medium", "high"] }
        },
        "limit": { "context": 524288, "output": 131072 }
      }
    }
  }
}
```

После миграции вариант выбирается в модели как `provider/model#variant`
(например `lunaroute/muse-spark-open#high`) — проверено живым запросом.

> **OpenCode V2:** плагины автопереключения ключей полностью адаптированы под требования V2.
> OpenCode V2 подключает только **каталоги** плагинов (попытка указать отдельный `.mjs` файл приводила к ошибке `configured plugin path must be a directory`).
> Studio разворачивает полноценный пакет в `plugins/keypool-<slug>/` с `package.json` (`main: "index.mjs"`)
> и `index.mjs` (с нативным V2-экспортом `{ id, setup }`). Конфиг регистрирует каталог в массиве `plugin`.
> Это обеспечивает прозрачную ротацию ключей на уровне `globalThis.fetch`, поддержку мульти-заголовков и кулдаунов прямо в процессе OpenCode V2.

## Важно про Kilo / WorkBuddy / Cline / Roo

- **Kilo Code** и **WorkBuddy AI** хранят обычные файлы конфигурации, поэтому студия
  пишет их напрямую с бэкапом и атомарной заменой: `~/.config/kilo/kilo.json(c)` и
  `~/.codebuddy/models.json`. После записи приложение нужно перезапустить.
- **Синхронное удаление зомби-конфигов:** при удалении провайдера (кнопка с корзиной
  или эндпоинт `/api/remove-provider`) Studio автоматически ищет и удаляет связанные
  записи в `kilo.json(c)` и `~/.codebuddy/models.json`. Если в Kilo удаляемый провайдер
  был выбран моделью по умолчанию (`model: "provider/model"`), Studio автоматически
  переназначает `model` на первый оставшийся рабочий провайдер либо аккуратно удаляет
  указатель, предотвращая сбои запуска Kilo из-за «зомби»-ссылок. Все комментарии, отступы
  и сторонние поля в `kilo.json(c)` бережно сохраняются.
- **Cline** и **Roo Code** держат настройки во внутреннем хранилище VS Code
  (`state.vscdb`), формат нестабилен и зависит от версии. Прямая запись туда опасна,
  поэтому для них студия заполняет те же поля, что есть в их UI, и отдаёт JSON
  для «Add provider».
- **OpenChamber** использует конфиг OpenCode: применять провайдера нужно в opencode.
- **Verdent** принимает Anthropic-совместимый endpoint через BYOA (Claude Code).
- **Qoder** принимает Custom endpoint в Settings → Models (OpenAI Compatible или
  Anthropic Compatible) и в CLI `/model` → Custom; вручную `settings.json` не патчим.
- **Kiro** пока не поддерживает custom base URL (BYOK в kirodotdev/Kiro#3115);
  для него работает только сетевой прокси/TUN.

## env var для ключа (режим по умолчанию)

Галочка «$ENV» включена изначально. В конфиг opencode вместо ключа пишется ссылка
`{env:BAI_API_KEY}` (именно этот синтаксис понимает opencode — `$BAI_API_KEY` он
подставлять не умеет и отправил бы строку как есть), а имя переменной попадает в `env`.

Установить саму переменную нужно один раз. Проще всего — кнопкой **«Задать
сейчас»**, которая появляется рядом с именем переменной, когда она не задана:
утилита возьмёт ключ из поля формы и выполнит `setx` сама. Значение уходит на
локальный сервер один раз и не возвращается обратно — в ответе только длина и
область видимости.

Либо вручную:

```powershell
setx BAI_API_KEY "твой-ключ"
```

После этого перезапусти **службу** opencode:

```powershell
& "$env:LOCALAPPDATA\Programs\@opencodedesktop\resources\opencode-cli.exe" service restart
```

Обычного перезапуска окна недостаточно: фоновая служба OpenCode продолжает
работать со старым окружением. Кнопка «↻ перезапустить OpenCode» делает это
сама — она ищет CLI, идущий в комплекте с OpenCode Desktop (только он понимает
подкоманду `service`), и откатывается к `opencode` из PATH. Старая глобальная
установка CLI на команду `service` отвечает страницей справки — это и есть
симптом «нажал, а ничего не перезапустилось». Ключ остаётся вне конфига.

Установка возможна только в область **текущего пользователя**: машинная область
требует прав администратора, а ключ принадлежит пользователю, не машине. В
Linux/macOS кнопка не пишет ничего сама (нет однозначного файла профиля) — она
выдаёт готовую строку `export ...` для вставки в свой профиль.

**Поле «API key» в режиме `$ENV` не сохраняется в конфиг.** Туда идёт только
ссылка `{env:ИМЯ}`; введённый в поле ключ отбрасывается. Если при этом переменная
не задана, утилита показывает предупреждение и требует подтверждения перед
записью — раньше запись просто проходила и отчитывалась «✓ Применено», а
провайдер потом отвечал 401.

После сохранения и перезагрузки страницы поле может выглядеть пустым — **ключ не
потерян**. Сервер намеренно не возвращает значение env-переменной в браузер.
Вместо этого поле подписано «Сохранён в ИМЯ — введи новый ключ», имеет зелёную
рамку и пояснение под ним. Введи новый ключ только если хочешь заменить старый;
глаз показывает лишь то, что ты вводишь сейчас, а не секрет из окружения.

Под именем переменной сразу показано, задана ли она, и в каком виде:

| Что показано | Значит |
|--------------|--------|
| `✓ ИМЯ задана (N симв., пользователь)` | всё в порядке: значение в постоянных настройках и его видят новые процессы |
| `⚠ ИМЯ задана (N симв., система)` | то же для машинной области (нужны права администратора при записи) |
| `✓ ИМЯ задана (N симв., процесс)` | значение пришло только из окружения самого Provider Studio и может исчезнуть после перезапуска |
| `⚠ ИМЯ не задана` | opencode отправит пустой ключ и получит 401 |

Рядом с заданной переменной есть кнопка **«↻ перезапустить OpenCode»** —
она перезапускает службу через CLI, встроенный в OpenCode Desktop.

Зачем: OpenCode Desktop держит фоновую службу (`opencode serve --service`)
часами. Переменная, записанная через `setx`, появляется в реестре, но **не в
уже запущенном процессе** — закрытие и открытие окна эту службу не
перезапускает. Отсюда самый обидный сценарий: ключ записан, «✓ Применено», а в
чате — `Provide your … API key` или 401. Лечится только перезапуском службы
(или перезагрузкой), и теперь это одна кнопка.

Переменная ищется не только в окружении самого Provider Studio, но и в постоянных
настройках Windows (`HKCU\Environment` и системные переменные) — то есть там, куда
пишет `setx`. Поэтому переменная, созданная **после** запуска утилиты, определяется
корректно, без перезапуска.

Если снять галочку, ключ будет записан в конфиг открытым текстом — утилита
спросит подтверждение.

### 401 «Missing or invalid bearer token»

Самая частая причина — не сама ошибка в конфиге, а незаданная переменная.
`{env:FOO}` при отсутствующей `FOO` подставляется **пустой строкой**: opencode
отправляет `Authorization: Bearer` без значения, провайдер отвечает 401, и это
читается как «неверный ключ», хотя ключа просто нет.

Кнопка «Диагностика» находит это явно:

```
✕ Провайдер «atessa»: переменная ATESSA_API_KEY не задана — opencode отправит
  пустой ключ и получит 401. Выполни setx ATESSA_API_KEY "<ключ>" и перезапусти терминал
```

Проверка соединения и «Обнаружить модели» в этом случае тоже не идут в сеть, а
сразу называют причину — иначе провайдер вернул бы 401 и увёл в сторону.

### Защита системных переменных и токенов > 1024 символов

- **Защита критических системных переменных:** переменные операционной системы (`PATH`, `TEMP`, `TMP`, `COMSPEC`, `SYSTEMROOT`, `WINDIR`, `USERPROFILE`, `HOMEDRIVE`) строго защищены от изменений и удаления (`isProtectedEnvVar`). Ни автоисправление, ни ручной ввод, ни очистка сирот ни при каких условиях не могут затронуть эти переменные.
- **Поддержка длинных токенов через PowerShell:** стандартная утилита Windows `setx` имеет жесткий внутренний лимит и **молча обрезает значения длиннее 1024 символов**, из-за чего длинные JWT-токены и ключи сложных шлюзов незаметно портятся и возвращают 401. Provider Studio перехватывает ключи длиннее 1024 символов, предотвращает их обрезку и выдаёт безопасную команду для установки через PowerShell:
  ```powershell
  powershell -Command "[Environment]::SetEnvironmentVariable('ИМЯ_ПЕРЕМЕННОЙ', 'ЗНАЧЕНИЕ_ТОКЕНА', 'User')"
  ```
- **Очистка переменных-призраков (Ghost/Orphan Keys):** при удалении или переименовании провайдеров старые переменные ключей могут оставаться в `HKCU\Environment`. Studio включает:
  - Эндпоинт `POST /api/env-clean-orphans` для пакетной очистки;
  - Кнопку **«Удалить все сироты»** в панели **Env-аудита** в UI;
  - Предупреждение со списком переменных (`envOrphans`) в модальном окне подтверждения удаления провайдера.
  Поиск ведётся по шаблонам ключей (`KEY_LIKE_RE`: `*_API_KEY`, `*_KEY`, `*_TOKEN`, `*_SECRET`), сравнивается с используемыми ссылками `{env:...}` в активном конфиге и исключает защищённые системные переменные.

Два подводных камня `setx`:
- значение длиннее **1024 символов молча обрезается** (Studio защищает от этого через PowerShell);
- новое значение видят только **заново открытые** терминалы (для работающего OpenCode нажми кнопку «↻ перезапустить OpenCode»).

## «Провайдер недоступен»: кто виноват

Раньше любая неудача пробы выглядела одинаково — красная строка «недоступен».
Из-за этого лежащий сервер выглядел как испорченный ключ, и пользователь шёл
перегенерировать токен, с которым всё было в порядке. Теперь причина
разделяется:

| Что показано | Где проблема |
|--------------|--------------|
| `✓ доступен` | всё в порядке |
| `⚠ ключ не принят` | ключ был отправлен, сервер ответил 401/403 — ключ неверный или истёк |
| `⚠ нет ключа` | сервер ответил 401/403, но запрос ушёл вообще без ключа — поле `apiKey` пустое либо `{env:VAR}` указывает на незаданную переменную |
| `✕ сервер недоступен` | таймаут / домен не разрешается / соединение отклонено — сторона провайдера |
| `✕ прокси` | запрос не вышел наружу: прокси не отвечает или требует авторизации (407) |

Важное следствие: ответ **401 означает, что сервер жив**. Такой провайдер
показывается жёлтым, а не зелёным и не красным — прежняя логика считала его
полностью работающим, потому что эндпоинт ответил.

В диагностике к причине добавляется расшифровка: `таймаут — сервер не ответил
вовремя, скорее всего он лежит или закрыт файрволом`.

Отдельно разделены «ключ отвергли» и «ключ не отправили». Оба случая дают 401,
но чинятся по-разному: в первом надо перевыпустить токен, во втором — заполнить
`apiKey` или задать переменную окружения. Раньше пустой ключ показывался как
«ключ не принят», и пользователь шёл менять токен, которого вообще не было.
Признак берётся не из текста ответа, а из того, ушёл ли в запросе заголовок
`Authorization`/`x-api-key`.

### Что бесплатно, а что нет

В списке моделей у каждой строки видна цена за 1M токенов или метка `free`.
Источник вердикта важнее самого вердикта, поэтому он отслеживается явно:

| Источник | Что значит |
|----------|------------|
| тариф (`access_tier`) | провайдер сам объявил модель бесплатной или платной — факт |
| цена (`pricing`) | цена пришла и равна нулю — факт |
| название (`free?`) | цен нет, но в id есть `:free` — догадка, помечается вопросом |
| `цена ?` | провайдер не отдаёт ни тарифа, ни цен — неизвестно |

Разница не косметическая. У одного из проверенных провайдеров 36 бесплатных
моделей из 102, но `:free` в названии есть лишь у 17 — фильтр по имени скрывал
бы больше половины. В обратную сторону: провайдер, отдающий только `id` и
`owned_by`, не даёт оснований называть модель бесплатной, поэтому она
показывается как «неизвестно», а не как `free`. Отсутствие цены (`null`) и
нулевая цена (`0`) — разные вещи, и в конфиг пишется только известная цена.

Единицы приводятся к одному виду: объявленный `unit` (`per_1m_tokens`,
`per_1k_tokens`, `per_token`) главнее, а если его нет — величина. У OpenRouter
цена идёт в долларах за один токен, у остальных обычно за миллион; без
нормализации одна и та же модель выглядела бы то в 10⁶ раз дороже, то дешевле.

**Лимитов по числу запросов здесь нет намеренно.** Проверенные провайдеры не
возвращают ни заголовков `x-ratelimit-*`, ни полей квоты в `/models` —
показывать было бы нечего, кроме выдуманного числа.

#### Бесплатные тарифы в пресетах

У пресетов со свободным доступом (OpenRouter, Groq, Google AI Studio, NVIDIA NIM,
Cerebras) есть заметка с лимитами, ссылкой на документацию самого провайдера и
**датой проверки**. Дата стоит не для красоты: сторонние подборки бесплатных LLM
устаревают молча. Например, на 2026-09-17 (перепроверено; впервые зафиксировано 2026-08-29) Cerebras прямо отвечает «Is there a
permanently free tier? No» ($5 кредитов на 30 дней), хотя популярные подборки
всё ещё обещают миллион токенов в день — поэтому в пресете написано, что
постоянного бесплатного тарифа там нет.

GitHub Models в пресеты не добавлен намеренно: эндпоинт отвечает HTTP 410
`github_models_retirement_brownout`, то есть его больше нет.

Числовые лимиты берутся только со страниц самого провайдера. Там, где точные
цифры отдаются скриптом и в HTML их нет (Google, Groq), числа не приводятся
вместо того, чтобы быть выдуманными.

### Прокси и VPN

Node **не читает** `HTTP_PROXY`/`HTTPS_PROXY` сам по себе. Поэтому за
корпоративным прокси или VPN-клиентом любая проба раньше отваливалась по
таймауту, и утилита винила провайдера, хотя запрос вообще не покидал машину.

Теперь прокси берётся (в этом порядке) из:

1. `https_proxy` / `HTTPS_PROXY` — для `https://`-целей;
2. `http_proxy` / `HTTP_PROXY` — для `http://`;
3. `all_proxy` / `ALL_PROXY`;
4. системных настроек прокси Windows (`Internet Settings`) — там, куда пишет
   GUI, если переменные не заданы.

`NO_PROXY` уважается, включая формы `.example.com`, `*.example.com` и `*`.
Поддерживаются `http`/`https`-прокси с авторизацией (`user:pass@host:port`);
для `https`-целей открывается CONNECT-туннель. SOCKS **не** поддерживается —
такой прокси честно игнорируется, вместо того чтобы притворяться и зависать.

Локальные адреса (`127.0.0.1`, `localhost`, RFC1918) через прокси не идут
никогда: ollama, LM Studio и vLLM живут именно там, и туннелировать их —
гарантированная ошибка.

Актуальный прокси показывается строкой в панели диагностики, поэтому видно,
шли пробы напрямую или через туннель.

#### Если VPN включают и выключают

Переменные `HTTP_PROXY`/`HTTPS_PROXY` уровня пользователя остаются заданными и
тогда, когда VPN-клиент выключен: они продолжают указывать на мёртвый
`127.0.0.1:10808`, и любой запрос из OpenCode падает с `ECONNREFUSED` — хотя
интернет есть. Лечится не отключением прокси, а списком исключений: OpenCode
(Bun) и студия читают `NO_PROXY`, поэтому достаточно вывести из-под прокси те
хосты, которые доступны напрямую:

```
NO_PROXY=localhost,127.0.0.1,::1,opencode.ai,.opencode.ai,lunaroute.com,.lunaroute.com
```

Результат: с включённым VPN всё остальное идёт через туннель, как раньше; без
VPN OpenCode и LunaRoute работают напрямую — конфиг не зависит от состояния
VPN. Побочный плюс: free-модели OpenCode перестают делить IP с остальными
пользователями выходного узла VPN, из-за чего раньше приходило
`abusive traffic from this IP` / `Rate limit exceeded`. Новое значение
подхватывается после перезапуска службы (кнопка «↻ перезапустить службу»).

Проверить, что маршрут именно такой: `Diagnostics` показывает «через прокси» /
«напрямую» рядом с результатом пробы.

#### TUN для приложений, которые игнорируют HTTP-прокси

Часть клиентов ходит в сеть своим транспортом и не читает `HTTPS_PROXY`: встроенные
модели OpenCode Zen, ряд Electron-IDE. Для них смена узла в v2rayN без TUN ничего
не меняет — запрос уходит напрямую с реального IP. Решение — включить **TUN** в
v2rayN (нужны права администратора): он заворачивает весь IP-трафик, включая такие
приложения. После смены узла перезапусти службу: `opencode service restart`.
Проверка: прямой `curl https://ipinfo.io/json` должен показывать нужную страну.

## Что не хранится на диске

- API-ключи **не** сохраняются в `data/providers.json` — только ссылка на переменную.
- Поэтому env-ключ после перезагрузки не отображается в поле: оно подписано
  «Сохранён в ИМЯ». Это не потеря ключа, а защита от повторной выдачи секрета в DOM.
- `/api/state` не отдаёт открытые ключи из конфига: форма получает маску
  `••••xxxx`, а при записи сервер сам подставляет настоящее значение обратно.
  Маска, не совпавшая с ключом в конфиге, отклоняется — не затирает его.
- `/api/envcheck` возвращает только факт наличия переменной, её длину и область
  (процесс / пользователь / система) — никогда значение.
- Значение переменной используется сервером только для исходящей проверки
  соединения и в ответ браузеру не попадает.
- «Скопировать JSON» и конфиги для Kilo/Cline/Roo подставляют placeholder вместо ключа.
- `data/providers.json` и `data/backups/` исключены из git через `.gitignore`.

## Доступ по сети

Сервер слушает только `127.0.0.1`: API без авторизации и умеет читать конфиг
opencode, поэтому доступ из локальной сети означал бы отдачу ключей любому в той
же сети. Дополнительно любой запрос с посторонним `Host` отбрасывается (защита от
DNS rebinding), а изменяющие запросы — ещё и при постороннем `Origin` /
`Sec-Fetch-Site` (защита от CSRF).

Открыть на все интерфейсы можно осознанно — при запуске выводится предупреждение:

```powershell
$env:PS_HOST="0.0.0.0"; npm start
```

## Проверка

```powershell
npm run verify        # весь набор
npm run verify:exe    # собрать .exe и проверить именно его
```

Наборы проверок:

| Набор | Что проверяет |
|-------|---------------|
| `verify-jsonc.mjs` | патчер: комментарии, отступы, однострочные объекты, идемпотентность |

## Известные ограничения

- «Проверить» считает ответы 401/403 достижимостью: сервер жив, но ключ не принят
  (в списке — жёлтая точка, не зелёная). Если ключ вообще не был отправлен, об
  этом говорится отдельно. Ответ 401/403 больше не возвращается как успех: раньше
  такой ключ засчитывался в пуле как прошедший.
- Проверка `/models` не гарантирует, что чат заработает: ключ может не иметь
  доступа именно к этой модели, модель может быть закрыта для страны, а квота —
  быть исчерпана. Это ловит только проверка боем — на последнем шаге мастера или
  кнопкой «Проверить все». OpenRouter это особенно заметно: каталог `/models`
  отвечает 200, а stealth-модель (например `stealth/crouton-alpha`) отдаёт
  `403 Provider returned error`, и настоящая причина лежит в
  `error.metadata.raw` — «This model is not available in your region». OpenCode
  показывает это как `AI.Error.Authentication: Provider returned error`, потому
  что читает только верхний уровень тела.
- Прямые запросы к OpenRouter без прокси с некоторых сетей блокирует WAF
  (`403 Access denied by security policy`). Provider Studio ходит через
  `HTTPS_PROXY` и видит 200, а харнесс, который прокси не использует, получает
  403. Проверяй, что у opencode в окружении тот же прокси.
- «Умные маршруты» — рекомендации, а не автоматический failover: OpenCode не
  переключает провайдера посреди запроса. Они меняют только `model`; автоповтор
  с другим ключом внутри одного провайдера делает keypool.
- На 1440×960 карточка редактора выше экрана и требует прокрутки: внутренняя
  двухколоночная раскладка карточки включается только с 1700px, иначе поля
  становятся слишком узкими.
- Пакетная проверка тратит настоящие запросы и на платных провайдерах стоит
  денег; за раз проверяется не больше 200 моделей.
- Каталог models.dev не знает про шлюзы-агрегаторы: он сопоставляется только по
  id модели, поэтому у переименованных моделей пробелы останутся незаполненными.
  Это осознанно — лучше пусто, чем чужие характеристики.
- SOCKS-прокси не поддерживается (нужен другой handshake); такой прокси
  игнорируется, и проба идёт напрямую.
- При работе через прокси имя хоста разрешает сам прокси, поэтому локальная
  защита от DNS-rebinding в этом пути не применяется — блокировка адресов
  метаданных по имени и по собственному резолву остаётся.
- Установка переменной окружения из интерфейса работает только на Windows и
  только в области текущего пользователя; значения длиннее 1024 символов
  (где `setx` молча обрезает строку) поддерживаются через готовую команду PowerShell.
- Определить, задана ли переменная, наверняка можно только на Windows (читаются
  все постоянные области). На Linux/macOS видно лишь окружение самого процесса,
  поэтому отсутствие переменной там — предупреждение, а не ошибка: её может
  подставлять обёртка, которую утилита не видит.
- Проверка соединения по умолчанию **разрешает** loopback и локальную сеть — иначе
  ollama, LM Studio и vLLM было бы не проверить. Запросы к метаданным облака
  (`169.254.0.0/16`, `metadata.google.internal`) блокируются всегда. Полностью
  запретить локальные адреса: `PS_BLOCK_LOCAL_PROBE=1`.
- Kilo и WorkBuddy патчатся напрямую; Cline / Roo — только инструкцией, потому что их
  настройки лежат в `state.vscdb`. Kiro не принимает custom endpoint — только TUN.
- Собранный `.exe` под конкретную ОС и архитектуру: он содержит копию текущего
  `node`, кросс-сборки нет.
- Пути к конфигу рассчитаны в первую очередь на Windows (учитывается `XDG_CONFIG_HOME`).

## Несколько конфигов и откуда бэкап

- Переключатель конфига в шапке — настоящий: диагностика, проверка, бэкап,
  импорт и восстановление работают с выбранным файлом, а не с файлом по
  умолчанию. Хеш для защиты от concurrent-правок тоже берётся из него.
- Каждый бэкап помнит файл, из которого снят (видно в списке). Восстановление
  пишет в исходный файл, а не в тот, что открыт в интерфейсе.
- Путь к конфигу, пришедший по HTTP, принимается только если это известное
  место (кандидат из списка или `OPENCODE_CONFIG`). Чужой путь игнорируется —
  эндпоинты не работают читалкой/писалкой произвольных файлов.
- Откат («Отменить») отказывается работать, если файл изменился после
  откатываемой записи: молча затирать чужие правки нельзя, восстанови из
  бэкапа вручную.
- Русские названия провайдеров транслитерируются в ключ (`БайТест` →
  `baytest`), а не схлопываются все в один `provider`.
- Обновление моделей опрашивает провайдеров параллельно (до 3 одновременно),
  порядок в плане — как в конфиге.
- Самопроверка честно проверяет именно запись (право W_OK на файл или каталог),
  а не чтение.

## Защита от блокировок файлов в Windows (NTFS File Locking)

Запись файлов конфигурации (`opencode.jsonc`, `kilo.jsonc`, `models.json`) производится атомарно: данные сначала сбрасываются во временный файл в том же каталоге (`.имя.pid.hex.tmp`), после чего заменяют целевой файл через `renameSync`.

На Windows файловая система NTFS регулярно удерживает кратковременные блокировки файлов:
- фоновые службы антивирусов (Windows Defender) и поисковые индексаторы кратковременно открывают изменённые файлы;
- файловые наблюдатели OpenCode (`chokidar`), VS Code и расширений перехватывают события записи;
- попытка выполнить `renameSync` по заблокированному дескриптору завершается ошибками `EBUSY`, `EPERM` или `EACCES`.

В `src/paths.mjs` реализован защитный механизм **NTFS File Locking Retry**:
- при возникновении ошибки блокировки утилита выполняет до **8 повторных попыток** замены;
- между попытками используется экспоненциальный backoff (от 25 мс с удвоением до 200 мс) со случайным джиттером (+0..30%);
- задержка выполняется синхронно через `sleepSync` (на базе `Atomics.wait`), не блокируя event loop Node.js;
- в случае неустранимой ошибки временный файл гарантированно удаляется через `unlinkSync`, предотвращая появление мусора на диске.

## Умный аудит

Едет внутри каждой диагностики, отдельным запросом ходить не надо:

- один id модели у нескольких шлюзов — с пометкой, где дешевле;
- модель по умолчанию стоит не на самом дешёвом источнике — warn с кнопкой
  «Сделать основным» (та же защищённая запись через хеш, что везде);
- модели без limit/cost — opencode их угадывает, аудит показывает сколько;
- оценка гигиены: 100 − 10 за warn − 3 за info, формула зафиксирована
  в `src/smart-audit.mjs`.

Чистая статика, сети не касается — считается миллисекунды.

### Умные маршруты

После загрузки состояния в «Обзоре» появляется блок **«Умные маршруты»**. Он
ранжирует уже настроенные модели и показывает до четырёх вариантов:

- **Основной** — лучший баланс контекста, reasoning, tools и цены;
- **Быстрый** — самый дешёвый/бесплатный вариант с достаточным контекстом;
- **С картинками** — модель с image-входом;
- **Резерв** — другой провайдер или следующая модель, если основной маршрут
  перестанет отвечать.

Если диагностика уже запускалась, её результаты влияют на выбор: недоступные
провайдеры и провайдеры с непринятым/незаданным ключом уходят вниз, а не
предлагаются как здоровые. До диагностики варианты помечены «не проверен».

Кнопка **«Сделать основной»** меняет только top-level `model` (одна строка
конфига), с проверкой хеша, бэкапом и откатом. Это **не** автоматический
per-request router: OpenCode не умеет нативно переключаться между провайдерами
посреди запроса. Автоматическая ротация есть только для ключей одного
провайдера — через пул keypool. Поэтому маршруты в Studio — честные
рекомендации + быстрое переключение основного, а не обещание несуществующего
fallback.

### Цена за токен и подписки

`cost` в конфиге — это цена **за токен**, а не стоимость подписки. У шлюзов с
фиксированной оплатой (LunaRoute: $19.99–$499.99/мес за параллельные запросы,
без тарификации токенов) предельная цена токена равна нулю, поэтому честная
запись — `"cost": { "input": 0, "output": 0 }`. Это не заглушка ради оценки:
OpenCode считает `$0.00` за сессию ровно потому, что за токены действительно не
списывают. Подписка в `cost` не выражается — её видно только в биллинге шлюза.

Без `cost` аудит ставит `info` «траты не оценить» и оценка падает до 97; с
заполненной ценой — 100/100.

# Provider Studio

Локальный редактор провайдеров и моделей для [opencode](https://opencode.ai) —
с проверкой ключей боем, а не на веру.

Добавить свой AI-провайдер в `opencode.jsonc` руками несложно, пока всё
получается с первого раза. Проблема в том, что ошибка обычно всплывает
позже и молча: опечатка в Base URL превращается в 404 на каждом запросе,
неверный формат API — в пустой ответ, забытая переменная окружения — в
провайдера, которого просто нет в списке. Provider Studio закрывает этот
разрыв: сначала пробный запрос к живому серверу, потом запись в конфиг.

Работает и с **OpenCode V1 / V2**, **Kilo Code**, **WorkBuddy AI**, **Cline**, **Roo Code**,
**ZCode**, **DeepSeek Harness** — с любым harness-ом, где есть кастомные эндпоинты.

Интерфейс на русском. Рантайм без зависимостей — чистый Node.js.

## Что умеет

**Ключи не попадают в конфиг.** В файл пишется ссылка `{env:GROQ_API_KEY}`,
само значение уходит в переменные окружения пользователя. Конфиг можно
показывать, коммитить и пересылать. Тесты отдельно проверяют, что литерал
ключа не просачивается ни в файл, ни в diff, ни в предпросмотр.

**Проверка боем.** Кнопка отправляет настоящий запрос настоящей модели и
разбирает ответ. Пометки различают пять состояний:

| | значит |
|---|---|
| ✓ | модель ответила |
| ₽ | ключ рабочий, но модель требует оплаты или депозита |
| ↻ | шлюз отклонил запрос временно — стоит повторить |
| ✕ | не отвечает |
| — | ещё не проверялась |

Разница между ₽ и ✕ важнее, чем кажется. «Access restricted. Deposit
required» — это тариф, а не ключ; выбрасывать ключ не нужно. Пустой
403 — тоже не отказ по ключу: на одном из шлюзов он выпадает примерно
раз из шести на **рабочем** ключе, а настоящий неверный ключ возвращает
401 **с текстом**. Поэтому пустой 403 помечается как временный, а не
как «ключ мёртв».

**Пакетный прогон.** Проверяет все модели провайдера сразу, с
троттлингом. Транспортные сбои (таймаут, обрыв) повторяются один раз:
две модели в тестовом наборе отвечают за 4.6 с примерно через раз, и
одна попытка врала бы в половине случаев. Отказ по самому ключу
останавливает пачку — но только пока ни одна модель не прошла, иначе
это ошибка конкретной модели, а не аккаунта.

**14 пресетов.** OpenRouter, Google AI Studio, NVIDIA NIM, DeepSeek,
Anthropic, OpenAI, Groq, Together AI, Mistral, Cerebras, Z.ai, Ollama,
LM Studio + ручной ввод. Base URL, формат API и имя переменной
подставляются сами.

Отметки о бесплатных тарифах датированы днём проверки, а не взяты из
головы. Если на странице провайдера точных чисел нет — их и не будет в
карточке. Cerebras прямым текстом отвечает «Is there a permanently free
tier? No», поэтому у него отметки нет. GitHub Models отдаёт HTTP 410 —
пресет запрещён.

**Справочник models.dev.** Подтягивает контекст, лимиты и возможности
моделей. Заявленное провайдером не перезаписывается, а **цены не
переносятся никогда**: 155 идентификаторов бесплатны у одного шлюза и
платны у другого. Лучше пустая клетка, чем чужая цифра.

**Диагностика.** Отдельно отвечает на вопрос «сервер недоступен или
ключ не тот» — это разные проблемы с разным лечением.

**Ничего не пишется без подтверждения.** Сначала обычный diff, потом
запись, перед каждой правкой — резервная копия.

**Пул ключей и ротация для OpenCode V2.** Поддержка нескольких запасных ключей
с автоматическим переключением. Для OpenCode V2 плагины генерируются в виде
пакетов-каталогов `plugins/keypool-<slug>/` с `package.json` и `index.mjs`
(с экспортом `{ id, setup }`). Поддерживаются мульти-заголовки авторизации
(`x-goog-api-key`, `api-key`, `x-api-key`, `Authorization: Bearer`).

**Суточные лимиты vs минутный RPM-троттлинг.** Тонкое распознавание дневных квот
(Groq RPD/TPD, Cerebras, OpenRouter stealth) выводит исчерпанный ключ из ротации
на сегодня. Минутный троттлинг (Gemini 15 RPM, HTTP 429) ставит ключ на временный
кулдаун (60 с) с экспоненциальным backoff, не выводя его из пула.

**Синхронная очистка зомби-конфигов.** При удалении провайдера Studio не только
чистит `opencode.jsonc`, но и синхронно удаляет связанные записи в Kilo Code
(`kilo.jsonc`) и WorkBuddy AI (`models.json`), автоматически переназначая
default-модель.

**Защита окружения и удаление Ghost Keys.** Системные переменные (`PATH`, `TEMP`
и др.) защищены от любых модификаций. Ключи длиннее 1024 символов защищены от
молчаливой обрезки `setx` через генерацию PowerShell-команды. Оставшиеся брошенные
ключи в `HKCU\Environment` удаляются в один клик через кнопку «Удалить все сироты»
в панели «Env-аудит» (`/api/env-clean-orphans`).

**Защита от блокировок NTFS.** Атомарная запись через временный файл с защитой
от блокировок фоновыми антивирусами и индексаторами Windows: до 8 повторных
попыток `renameSync` с экспоненциальным backoff (25–200 мс) и рандомным джиттером.

## Установка

Нужен Node.js 20+ (разрабатывалось на 24).

```bash
git clone https://github.com/<you>/provider-studio.git
cd provider-studio/provider-studio
npm start
```

Откроется `http://localhost:5173`. Если порт занят — возьмёт следующий
свободный. На Windows можно просто дважды кликнуть
`start-provider-studio.cmd`.

Для запуска зависимости не нужны вообще: `npm install` требуется только
для сборки `.exe`.

### Один файл, без Node

```bash
npm install
npm run build
```

Получится `dist/provider-studio.exe` (~88 МБ — внутри целый Node-рантайм).
Самодостаточен: ни Node, ни папка `public/` рядом не нужны.

Последний шаг сборки — запуск самого exe с самопроверкой: он отдаёт
страницы, `/api/state` и проверяет, что обход каталога по-прежнему
блокируется. Сборка падает, если UI недостижим. «Собралось» здесь
значит «работает».

## Проверка

```bash
npm run verify
```

Семнадцать наборов, свыше 1200 проверок, без сети и без моков поверх
моков — поднимается настоящий HTTP-стенд, который умеет притворяться
сломанным шлюзом: отдавать пустой 403, молчать до таймаута, отвечать
400 вместо 401.

Тесты проверялись мутациями: в рабочий код намеренно вносилась поломка,
и набор обязан был упасть. Проверка раскладки, например, переписана
после того, как незакрытый CSS-комментарий съел правило и старый набор
этого не заметил — он искал текст регулярками и спокойно находил его
внутри мёртвого комментария.

## Чего он не делает

- Не угадывает цены и лимиты для моделей, которых нет в каталоге. У
  многих шлюзов свои имена вроде `claude-opus-4-8` — такие остаются
  пустыми намеренно.
- Проверка боем тратит настоящие деньги, если модель платная. Запрос
  минимальный (16 токенов), но не бесплатный.
- За раз проверяется не больше 200 моделей.
- Не менеджер ключей и не хранилище секретов. Значения живут в
  переменных окружения ОС, со всеми вытекающими.
